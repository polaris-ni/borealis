## 0 本稿的性质与三条边界

- 本稿管「面板上有哪些控件、每个控件收哪个键、改完什么时候可见」，不管像素层序（那是 `codespec/RENDER_UI.draft.md` 与 `codespec/UI_SELECTION.draft.md` 的职责），也不管窗口 chrome 的尺寸阶梯（沿用 `codespec/UI_OVERVIEW.draft.md` §2）。
- 三条不在本稿范围：连接域的**建档表单**（档案树、五步向导、SSH / 串口表单在屏 2 `codespec/UI_CONNECTIONS.draft.svg`，本稿只画四域的**默认值**）；SFTP 双栏 / SSH 隧道 / 密钥管理器（`codespec/UI_OVERVIEW.draft.md` §5 的未画清单）；`SPEC.FEAT.PREF.07` 的快照回滚与导出导入**本体**（M2 腿，本稿只处置「导入配置 / 导出配置」两个按钮的呈现，见 §4E）。
- 「即时生效」在本棒有两条物理边界，先写明白免得评审时各说各话：
  - ① **这条边界已由 §5 S4 的两条运行期入口闭合**（2026-10-04 落地，判据入册为裁决 **7.53**）。登记时的实测事实照录以免形成伪死链：`ui::TerminalView` 的外观与交互入参**全部**挂在构造函数上（调色板、参考字体、`ui::Typography`、内边距、闪烁周期、`InteractionOptions`、回退链七个形参），已有的四条接缝（`set_overlay_host` / `set_presentation` / `set_grid_size_sink` / `set_key_pre_filter`）没有一条能改颜色或字号。如今的形态：`apply_appearance(Appearance)` 收「外观包」六项（调色板 / 参考字体 / `Typography` / 内边距 / 闪烁周期 / 回退链），`apply_interaction_options(InteractionOptions)` 收交互包；七形参构造入口保留为委托适配器，故既有像素用例与装配层零改动。可改的仍是**外观 + 交互两域**——`cursor_shape` / `cursor_blinking` / `ambiguous_width` 三条照 §7 那条走构造期注入，本闭合不改变它们的「下次会话生效」。
  - ② **四个入参在「建会话」那一刻取用**（`scrollback_limit`、`connection.local_shell`、`connection.startup_directory`，以及 §7 那三个尚无接缝的会话侧缺省），运行期改它们不会重放既有会话。判据因此是「下次会话生效」，而不是把它谎报成即时。

## 3 与 SVG 的九处出入（以本稿为准）

1. **主题卡的第 7、8 张名字不同**：SVG 画 Tomorrow Night / Daylight，`include/borealis/config/themes.h` 实际八套是 dracula / nord / solarized-dark / one-dark / gruvbox-dark / monokai / **campbell / tokyo-night**。以代码为准（AGENTS.md §4.2 第 12 条：文档与代码冲突时以代码运行时为准并回填文档）。图标 2 那句「内置 ≥8 套」两边都成立，问题只在名字。
2. **第五类「高级（韧性/日志）」撤销**：需求原文与 schema 都是**四分类**，多出一类就是「另起一套键名」。其两项内容各有归处——会话日志两键归**连接页**；配置韧性不是可配项而是**启动事件**，归 §7 的降级对话框。
3. **「语言 Language」下拉不建可用态**：`SPEC.FEAT.PREF.05` 未开工——本仓从未向 `i18n::default_string_table()` 注册过译文，也没调过 `set_default_locale`（`src/`、`include/`、`tests/` 三处 grep 均零命中）；框架的语言走 `Provider<Locale>`，没有进程级 locale 量。按人已拍板① 画**灰置区段 + 延后角标**。
4. **「跟随系统浅色」开关撤销**：框架 `environment/media_query.h` 的 `MediaQuery` 无亮度或 appearance 字段（全 include grep `brightness` 零命中），即**没有数据源**；且 `SPEC.FEAT.PREF.01` 原文只写「UI 主题暗色优先、跟随 Aurora `Theme::dark()` / `ThemeScope` 体系」，没要求跟随系统。这条属「图上画了需求没要的东西」，按 AGENTS.md §4.1 第 1 条不实现。
5. **「多行粘贴警告」开关撤销**：`SPEC.FEAT.INTERACT.03` 把多行警告写成**固有行为**而非可配项，schema 里没有该键；逐行节流的块间隔按裁决 7.33④ 是库内常量、明确「暂不开配置键」。画一个没有键可写的开关就是空位。
6. **「OSC 52 剪贴板读取（三态）」不画控件**：属 `SPEC.FEAT.CONN.12`（M4），schema 无键。处置与第 5 条同理，改在终端页脚注一行说明它随该条落期入 schema（S15 的「无键不画控件」档）。
7. **「CJK 缺字回退链」从静态串改为可重排列表**：SVG 画的是字面串「微软雅黑 → 等线 → Noto Sans CJK」，而真值是 `std::vector<std::string>` 且顺序即语义；裁决 7.50 已接消费。形态见 S8。
8. **快捷键页首版只读**：SVG 画了红字「冲突：与「复制路径」重复」与「恢复默认键位」按钮。当前 overrides 无消费方、重绑需要录制件，且本仓键位通道不经 `ShortcutRegistry`（裁决 7.51③），故首版只呈现注册表实际值与冲突标注，「重绑」「恢复默认」两处挂延后角标（S9）。
9. **右侧预览盒从手绘静态图改为真实绘制路径**：SVG 那一盒是逐格手画的示意。裁决 7.25⑩（N5）明令「用真实绘制路径：预览区复用终端视口的同一套格参数与合成链路」，静态假预览**不予采用**。注入方案见 S7。**该盒的落位本稿就地更正**（人已拍板 2026-10-05，裁决 7.64⑩）：不取 SVG 的「右端一整条」而取**卡片底部一条 140 dp 高的横条**，根据与代价见 §1 的「实时预览盒」行与下面的 F-e。

**一处「文有图无」**：状态栏 10 项开关。裁决 7.25⑧（N3）明写「每项一个开关入 `borealis::config`，入口随设置面板」，而 SVG 没有这一组。本稿把它定在**外观页末段**（S10），并按 `codespec/UI_OVERVIEW.draft.md` §6.5 的既有口径登记为**配图落后项**——生图脚本未入库，故本轮不手改 SVG、不重出 PNG，以本文件为准。

## 4 逐页判据

**A. 外观页**

- A1-a：主题卡带四色样例，选中卡在右下角给勾；**卡片名字必须逐字等于 `themes.h`**（判据即 §3 第 1 条的反向核对）。两处措辞已由实现修正（裁决 7.61①②，原文按当时的推断写、代码里没有第三个可指的对象）：「显示名」＝**存储键名**（`dracula`，不是 `Dracula`，也不是任何中文名——预置表只有 `name` 一个字段，另立一张显示名表就是视觉稿与 schema 之外的第二份真值源）；四格样例是**前 / 背 / 光标 / 一个基本色**而不是「强调」——`PaletteSpec` 里没有强调色，八套预置的 `ChromeOverride::accent` 又全为空（chrome 覆盖不在首版，裁决 7.26②），故「强调」那一格**没有数据来源**。
- A1-b：「自定义」不是一张第十卡，而是「任一 palette 槽被改过」后的**状态**：palette 编辑区常驻在主题卡下方，改一格即在主题行挂「自定义」角标（与 SVG 的「自定义」小签同形态）。实现口径（裁决 7.61④）：判定对象是**全部五档 palette 槽**（16 格色板 + 前景 / 背景 / 光标 / 选区四张单格槽），只比 16 格的实现会把「改了光标色」静默放行。
- A2-a：16 色重映射是**一格一格点**而不是 16 个常驻输入框：点一格 → 下方给出该格 HEX 输入、当前值与「恢复主题默认」（S6）。本条真正禁止的是「**16 个常驻输入框**」，实现形态是把**那一只常驻**输入框指向所点的那格而不是每格现建一个（裁决 7.61③：`Modifier` 没有可见性位，按创建/销毁表达「只有选中格有输入框」就得整块重建浮层，那会抹掉滚动偏移与输入焦点）。
- A2-b：`cursor_color` 与 `selection_color` 各带「未配」档，且「未配」与「配成黑色」在 UI 上必须可区分——这是裁决 7.27③ 那条两态在界面上的兑现。
- A2-c：最小对比度阈值输入旁**实时显示**当前前景/背景的 `ui::contrast_ratio` 读数与是否达标（WCAG），否则用户改完不知道有没有用。
- A2-d：所有色值输入框**都没有 alpha 位**——`palette.*` 的槽经配置往返只有 `#RRGGBB`（装载侧只收 7 字符，写回不输出 alpha），给一个存不回去的输入框比不给更糟（用户以为改了透明度，重启就没了）。透明度若将来要可配，须先给 `PaletteSpec` 的落盘形态补 alpha，那是一条 schema 变更而非面板改动（S14）。
- A3-a：字号、行高、字距三个步进器各自显示单位（`pt` / `×` / `dp`）。**单位落在反向核对件的新列 `SettingsControl::unit` 而不是面板里**（面板另列一张按键的表就是第二个真值源，裁决 7.56）；带后缀的一共四行——`font_size_pt` = `pt`、`font_line_height` = `×`、`font_letter_spacing_dp` = `dp`、`cursor_blink_period_ms` = `ms`，其余数值行**不留**（SVG 上「视口内边距」就是一个裸数字，补后缀就是自造）。**一处图文冲突按代码为准**：SVG 那格写「字距 0.0 ×」，而该键的量纲是 dp（裁决 7.46② 的 `lround(dp × scale)` 量化），故本判据取 `dp`，图上那个 `×` 是稿的笔误，不改 SVG（改一处就得重出 PNG，而这一格不影响任何其它判据）。三者一改即触发视口重取整格度量与行列数（S4 已落：`apply_appearance` 在装链后紧接触发一次度量重取，故三个排版量与回退链都经这一条入口生效，裁决 7.53①②）。
- A3-b：「字体连字 ligature」保留 SVG 的**延后子项**角标且灰置——它是需求原文的延后观察项，不得画成可用态（`UI_OVERVIEW` §2.3）。
- A4-a：等宽字体下拉的候选来自 `render::list_font_families(monospace_only = true)`，且**只在装配阶段取一次**（该入口首次调用是同步 IO，裁决 7.46③）；面板不得为它再取一遍目录（S16）。
- A4-b：配置里写错的族名会**静默回落**（框架族名逐字节精确、区分大小写），故面板打开时若当前生效族 ≠ 配置族，须在字体行下方显示回落留痕，而不是把下拉显示成那个不存在的族。
- A4-c：**字体族行的形态＝行内一枚常驻按钮（标签是当前生效族名）＋ 点击经场景根 `OverlayHost` 弹一列候选浮层**（人已拍板 2026-10-06，裁决 **7.69①**）。本条登记时写的是「下拉」，而那一档被 §6 第 10 条末的框架形态约束挡住（列表行内不得使用覆盖绘制不占布局的控件）；本形态不是绕开它：行内那枚按钮**正常占布局**，覆盖绘制发生在场景根的浮层里。浮层在面板浮层**之后** add，按 `OverlayHost` 的「`on_paint` 前向 / `on_hit_test_chain` 逆序」它天然在最上层——点击落在候选列内由浮层吸收，落在其外则该链返回空表而继续下探到面板，故「点外部即关」由本仓自驱（裁决 7.41③ 同一条：框架的 `OverlayHost::handle_outside_click()` 无生产调用点）。**一条连带改动**：面板遮罩那枚「点空白处关面板」的 `clickable` 在浮层打开期间必须**只关浮层**，否则第一次外部点击会把整块面板一起撤掉。
- A4-d：**候选池＝等宽全集；次序＝族名逐字节字典序，并把「当前配置值」与 `kDefaultMonospaceFamily`（Cascadia Code）固定置顶两档**（同值时合一，其余照排；人已拍板 2026-10-06，裁决 **7.69②**）。这条补的是本稿登记时那句「本机 200+ 族如何挑选与排序没有依据」：依据是 `list_font_families(monospace_only = true)` 已把 200+ 收窄到 20+ 档（等宽按度量判定，裁决 7.46③），而字典序 + 当前值置顶让「确认现在用的是哪一族」与「找回并改回去」两条动作各一步可达。档数超出可视高度时靠浮层内部 `Scroll`，**不做**分页也**不做**过滤框——与 A5-a 那一池的分工不同（那一池要「从全集里找一族加进链」，本池只选一档）。
- A4-e：**浮层的锚点只能取同一次 Press 事件的坐标对，不得由 `paint_bounds()` 折算**（读源结论，裁决 **7.69③**，细则与代价见 §6 第 14 条）。派发器 `deliver_chain` 逐节点写 `e.local_position = global - it.origin`，且 `it.origin` 自 G31 回货起与绘制原点逐位相等，于是 `position − local_position` 就是该控件盒原点**在内容坐标系里的读数**（本条登记时写作「自身的全局内容盒原点」，该句随实现腿实测就地更正，裁决 **7.70②**），故还须减掉行区当时的 `offset_y()`（公共面取到这一个量）才落回窗口坐标，再配 `size().height` 即得下沿。反之，行区是 `Scroll`，其内容子节点的绘制盒处于**离屏缓冲帧**（框架三处自陈该限制），拿它做「内容坐标 + 滚动偏移」的应用侧折算就是把 `scroll.h` 的 §geom 契约复制进本仓，而 `buffer_origin_y_` 根本不公开。**已落 2026-10-06**（裁决 **7.70**，`src/ui/settings_panel.cpp` 的 `AnchorButton` / `build_family_section()` / `open_family_popup()` + `itest_settings_panel.cpp` 的 `clicking_the_font_trigger_anchors_a_popup_at_that_press_below_the_button`）：A4-b / A4-c / A4-d / A4-e 四条判据至此各有证人，且上面那句「`paint_bounds()` 与派发对同值」的旧口径被实测否证（同帧 748 对 826），据此登记 **G36**——本件那条「自持 `Scroll` 句柄做折算」的形态是过渡形态，回货即撤。**回货已至（2026-10-06 同日，Aurora `416b27bc`，裁决 **7.73**），该句预诺兑现**：锚点改取 `Widget::window_bounds()`（新增的公共入口，查询时沿布局父链现算、恒窗口逻辑 dp）配 `size().height`，查不到即不弹；`AnchorButton` 子类与面板自持的 `row_area_` 两处一并撤除（全仓无残留，实现侧净减 47 行）。故本条正文那句「只能取同一次 Press 事件的坐标对、不得由 `paint_bounds()` 折算」的**前半句作废而后半句仍成立**——`paint_bounds()` 至今仍是缓冲帧读数，而坐标对那条路径本身已被框架那条尚未修的 `HitNode.origin` 缺陷（缺 `offset_y_`）证明不宜作几何真值源，细则见 §6 第 14 条末段。
- A5-a：回退链区段显示顺序、支持上下移动与删除、末尾「添加族」入口；链容量上限取框架 `AURORA_TEXT_FALLBACK_CHAIN_MAX`，超限时须显式提示「已截断到前 N 项」——因为截断发生在框架侧而**对用户不可见**（裁决 7.50）。**实现形态（裁决 7.62①，本条的「下拉」三字按代码现状就地更正）**：「添加族」不是一只 `Dropdown` 而是一池**常驻候选按钮 + 一只过滤输入框**（一次显 6 档，按过滤词收窄、其余档 `show = false`），三条理由：⑴ 本机字体目录实测 200+ 族，任何下拉形态都要溢出窗口或另立滚动件；⑵ 该仓 §3.2.2 新立的形态约束（列表行内不得使用覆盖绘制不占布局的控件）；⑶ **G31** 令行内下拉的本地坐标错位 8 dp 而点不准（**该条已随同日回货闭合**，裁决 7.64②③④；本条取常驻池的理由剩 ⑴ 与 ⑵ 两条，形态不因此改）。零盒仍占布局，故这一池不属该约束，也不受 G31 影响（按钮不分带，命中即整枚）。上限那条照 A5-a 原文兑现：**达框架上限即关死追加口**（候选按钮一律 `set_enabled(false)`），而非「让点了没反应」。
- A6-a：光标三形态 + 闪烁开关 + 闪烁周期；三档形态与 `term::CursorShape` 的 Block / Underline / Bar 逐一对应。SVG 那句「光标形态随 DECSCUSR 切换」保留：面板给的是**缺省档**，远端之后以远端为准（`settings.h` 该键的注释）。
- A7-a：视口内边距步进 `[0, 64]`，改完预览盒与主窗口的**行列数同时变**——它是唯一一个会改变网格尺寸的键，判据要断「不出现半格」。
- A8-a：标签名优先级下拉两档（手动重命名优先 / OSC 标题优先）。它归外观域的理由已在 `settings.h` 写明（改的是标签栏那行字，不改会话字节），面板因此**不放**进快捷键页。
- A9-a：状态栏 10 个开关成组出现（S10），文案与 `codespec/UI_OVERVIEW.draft.md` §2 屏 1 的状态栏条目逐一对应，组顶加一行「入口先于消费方落地：关闭状态栏件尚未开工，本组改动只落盘」（S15 的延后档措辞）。

**B. 终端页**

- B1-a：scrollback 步进器上限 100,000，并在同一行显示当前值与「下次会话生效」角标（S11）——**不给**「立即重开会话」动作，那属工作区语义。
- B1-b：Ambiguous 两档带一句口径说明（窄＝本机 UTF-8 / SSH；宽＝GB18030 / GBK 串口一类），因为需求把这条写成裁决 7.15 的取值而非新行为。
- B2-a：右键三态、粘贴换行三策略、选中即复制、三项复制变换、断点集六个控件全部**即时**生效，判据是「改完不重开任何东西，右键与复制立刻按新值走」。
- B2-b：`word_delimiters` 输入框必须原样收字符（含引号、反斜杠、竖线），且**不做任何转义**；空串要在 UI 上说明「只有空格与制表断词」这一含义，否则用户会以为清空＝恢复默认（默认是 32 个 ASCII 可见标点）。
- B3-a：`encoding` / `bell` / `long_line` 三个控件按 S15 **照常可改可落盘** + 延后角标（**不灰置**——人已拍板于裁决 **7.68③**，落地见裁决 **7.74**，本稿原句「灰置」就地更正），且 `encoding` 同时标「下次会话生效」——两条标签不冲突：前者说没有消费方，后者说有消费方时的档位。
- B4-a：页脚注一行 OSC 52 读授权（§3 第 6 条）。

**C. 连接页**

- C1-a：本地 shell 与启动目录两项**可编辑且即时落盘**（消费方是下次建会话的装配路径），角标「下次会话生效」。
- C2-a：SSH 五项与串口六项**整组照常可改可落盘**，延后由两处文字表达——行尾「延后」角标 ＋ 落在该组首行之前的**组顶说明**（措辞须点名是哪个消费方还没开工），控件同时显示 schema 当前值。**本稿原句「整组灰置」已被人已拍板那条口径否证**（裁决 **7.68③**，落地与真控件证人见裁决 **7.74**）：把可用控件画成不可用会让「骨架全建」这句在交互面上不可验证，故「骨架全建」与「不谎报生效」两条改由**文字**而非灰置同时成立（人已拍板① 的那句「画控件、显示当前值」不变）。
- C3-a：会话日志两键按 `SPEC.FEAT.CONN.11` 的语义呈现：开关缺省关闭，且开启时在旁注一句「首次落盘会给出日志可能含密码 / 令牌的风险提示」——该提示属落期行为，本稿只登记文案位。
- C4-a：本页**没有**任何凭据输入（§2 表末那条）。

**D. 快捷键页**

- D1-a：只读表按「动作名 / 分组 / 当前组合键」三列，动作名走本仓 `StringTable` 词条（裁决 7.25⑬ N8：命令 id 一律英文入注册表，中/英词条由本仓维护）。<br>**行源与三列取数已由人拍板（裁决 **7.72②**），本稿原写的「按注册表逐条列出」由此细化为可执行口径**：行源是框架 `CommandRegistry::all()`（装配层折成 `ui::ShortcutCommandEntry` 交进纯逻辑件），动作名逐字取注册时的 `Command::title`（那条入口本身已走过本仓词条表，故面板**不查第二遍**，否则同一词条两处解析）、分组取 `Command::category`、「当前组合键」取注册表 `default_binding` 的框架 `KeyCombo::to_string()`。**覆盖表只贡献孤儿行**：`shortcuts.overrides` 里注册表查无此 id 的条目另列一行并挂「延后」角标，而**已注册**命令的覆盖条目既不产生行也不改写那一行——那张表当下无消费方（7.27②），把一条未生效的覆盖画进「当前组合键」就是谎报生效；孤儿行一律排在注册行之后、按覆盖表自身次序。
- D2-a：冲突标注来自**实际比对**而非硬编码文案；SVG 那行「与「复制路径」重复」只是示例形态。<br>**比对的两半与判据值已由人拍板（裁决 **7.72③**）**：⑴ 表内两两比对「实际绑定相同」；⑵ 每条注册行再与**本仓十二条分屏键位**（`ui::workspace_key_bindings()`）比对——那批键位不经 `ShortcutRegistry`（裁决 7.47②），而同一个组合键在派发上由快捷键层先消费（裁决 7.51③ 理由 (a)），故撞上了实际生效的是快捷键而分屏命令按不到，这一格不留给用户试。比对**吃 `term::KeyPress` 而非显示文本**：框架公共面没有 `KeyCombo::to_string()` 的反向解析（`key_name` 是单向表），在界面上比字符串就得自造一张键名反查表即第二真值源；修饰位只取 Shift / Ctrl / Alt / Meta 四位、键盘锁定态不参与，与 `workspace_command` 及框架 `KeyCombo::matches` 三处**逐位一致**（裁决 7.51①）。孤儿行只有文本因而**恒不参与比对**，其呈现是「延后」而不是「无冲突」。
- D3-a：「重绑」与「恢复默认键位」两处挂延后角标（S9），且**不给一个点了没反应的按钮**。<br>**纯逻辑件与界面腿均已落（2026-10-06，裁决 **7.72** + **7.75**）**：该页的表行由 `ui::build_shortcut_rows()` 给出（`include/borealis/ui/shortcuts_table.h` + `src/ui/shortcuts_table.cpp`，公共头不含 Aurora 类型），面板侧 `build_shortcuts_section()` 沿用主题卡 / 16 格色板 / 回退链三处的自绘先例把表体画成**四列**（列名「动作 / 分组 / 当前组合键 / 标注」），而**不用** `data_widgets.h` 那三件表控件（其 `on_paint` 形参一律 `/*ctx*/`，`Theme` 到不了且色值硬编码浅色，裁决 7.68①）。「不给一个点了没反应的按钮」的兑现形态随之从「只读摘要占位行」升级为「表体已画出而**没有一个提交入口**」：`ReadOnlyTable` 在 `is_editable()` 判假（该页那行是表头，其状态列取 `editable=false`），四列全是 `Text` 而无任何可点节点，故真点表体既不落盘也不广播、表单也不变脏——这一条由集成用例按**真实派发落点**守（先例 7.41 的 `context_menu()` 同口径，观测面另开 `shortcuts_rows()`）。延后档位按 7.68③ 的通则**一律可用而只落盘**，故本区段没有灰置档；「重绑」与「恢复默认键位」两处入口本身仍属延后，只在组顶说明一处文字里点名（`settings.note.shortcuts`）。

**E. 顶部动作**

- E1-a：「导入配置 / 导出配置」按 `SPEC.FEAT.PREF.07` 的 M2 腿挂延后角标；本稿不实现其对话框。**延后的是入口而不是口径**：凭据不落明文这条已由裁决 7.26⑥ 定死，`utest_config` 里已落的证人是「落盘文件递归扫键名不含 `password` / `passphrase` / `secret` / `token` / `private_key`」这一条禁列名单；导出件本体的凭据检查（导出的是内容而非仅键名，故名单比对不够）随 PREF.07 的 M2 腿一起落，其判据形态可复用同一思路。
- E2-a：标题区在面板打开时是「设置 / 修改即时生效」（**就地更正 2026-10-06**：原写的「· 右侧为实时预览」那半句随 F-e 的底部横条落位作废——预览的方位不属标题区文案，且面板本体自始只写「修改即时生效」，见裁决 **7.66①**）；面板是浮层而非换根（S1），故**不改**主窗口标题栏文案，SVG 里那条「Borealis — 设置」属绘图约定不是判据。

**F. 实时预览盒**

- F-a：预览用**独立**的一份 `Session` + `TerminalView`，不接管用户会话（否则会污染真实终端）。
- F-b：预览内容来自固定夹具文本（含 CJK 双宽、框线码点、16/256/真彩三色段、粗体与下划线、光标形态示范），与 SVG 画的 `$ borealis --preview` / 主题名 + 字号行 / 中文双宽行 / `┌──┐` 框线行 / red-green-blue 行同构。
- F-c：预览与主窗口共用同一套 `PaletteSpec`、同一份字体族目录、同一份排版选项，故「设置里好看、上屏不对」这类分叉在结构上不可能发生——这句是 SVG 自己写在盒下的判据，也是 N5 的动机。
- F-d：预览盒的行列数由其自身矩形算出，**不跟随**主窗口的网格。
- F-e（**人已拍板 2026-10-05，裁决 7.64⑩**）：预览盒落位取**卡片底部一条 140 dp 高的横条**，不取 SVG 的「右端 `x ≥ 1120 dp` 一整条」。根据是卡片宽 960 dp 而导航列占 200 dp，再切一条右给预览就把行区压到「标签 + 控件带（约 240 dp）放不下」；代价三条如实登记——① 行区可视行数随之减少（面板卡总高**不动**，故横条是从行区高度里扣的，长页要多滚一段）；② 预览自身矩形由此变成「宽 ≈ 928 dp × 高 140 dp」的扁条，其行列数按 F-d 现算故**行数少**（约 5～7 行 @14 pt），夹具文本的示范面要按这个高度收窄；③ 高度做成常量而非按内容算，以免夹具换字号时预览盒反过来改整页布局。**#115 开工即按本条落**，不再另立形态。**已按本条落 2026-10-06**（裁决 **7.66**），并补一条实施约束：那 140 dp **只能经控件级尺寸意图**下达（`preview_->view().height(aurora::px(140))`），挂在修饰链上的 `Modifier{}.height(140)` 会被 `ui::TerminalView` 自宣的 `fill()` 意图在测量之后**静默覆写**（框架 `Widget::layout` 跑完修饰链后还按 `width_/height_` 意图再覆写一次 `size_`）——实测缺那一句时横条占满 header 以下整段（506 dp）并把行区 viewport 压成 0 高。面板侧凡给视口定尺寸一律走该意图，见裁决 7.66③。

1. 「运行期换主窗口根」**有**公共入口（`Application::window()` 回主窗口 `Window *`，`present_root(Node&)` 是公开成员），但 `Application::open_window` 移交 `Window` 所有权且回的是 `WindowId`，故独立窗口要自己接派发与帧回调；换根那条的成本是视口的卸载-重挂与焦点重派（三条实测代价见 S1）。限制在**生命周期成本**而非可达性，故 S1① 取浮层形态。
2. `Preferences` 的 `binding` 是单向投递视图、不写回存储（该文件自陈写回须另调 `set`），且有 Binding 构造重载的控件恰为**四个**（`Switch` / `Checkbox` / `Slider` / `ProgressIndicator(Binding<double>)`，进度件只读无写回需求）→ 表单状态机归本仓（S3①）。
3. 无取色器（`pickers.h` 只有 `DatePicker` / `TimePicker`）→ HEX 文本输入（人已拍板③）。
4. `SpinBox` 不能键入数字（只能步进与前后缀），故带小数的量（行高、字距、对比度）用步进器 + 一个只读数值标签；要键入就换 `TextInput` + `FormField` 校验（S14 同一条校验腿）。
5. `Dropdown` 的 `options_` 私有且没有运行期 `set_options` → 面板打开时按当前配置构造，族名目录变了要重建面板（本棒可接受，因目录只在装配阶段取一次，S16）。
6. `MediaQuery` 无亮度字段 → 「跟随系统浅色」没有数据源（§3 第 4 条撤销）。
7. `ShortcutRegistry` 没有「暂停全部绑定」语义。它**有**逐条 `set_enabled(int id, bool)`（shortcuts.h 的 `add()` 回绑定 ID 并注明供 `remove`/`set_enabled` 使用），但 `bindings()` 返回的是 `ShortcutBinding` 副本而该结构**不含 ID 字段**，故「先枚举再逐条暂停」在只拿到注册表现状时走不通——`clear()` + `CommandRegistry::bind_shortcuts()`（该函数自陈幂等：先移除上次产生的绑定再重建）才是可组合的形态。**属可组合**，不登记缺口；代价是同期框架侧其他绑定一并暂停。本棒到 PREF.04 的缺口账目仍为 0。

11. **#116 的「快捷键只读表」用不上框架的三件表类控件**（2026-10-06 #116 / #117 依赖梳理棒读源实测，裁决 **7.68②**）：`widget/data_widgets.h` 的 `DataTable` / `TreeView` / `ListView` 三件的 `on_paint` **都不读 `ctx`**（形参一律写成 `/*ctx*/`，`data_widgets.h:169 / :335 / :561`），于是 `Theme` / `ThemeScope` 到不了它们；其实现体 `src/aurora/widget/data_widgets.cpp` 的色值全是**硬编码浅色**（表头底 `{246,246,248}`、表头字 `{60,60,65}`、单元格字 `{30,30,35}`、斑马行 `{249,249,251}`、选中与悬停 `Color(0,122,255,30)`），而公共面**没有任何色值 setter**、**没有 `set_enabled`**、**列定义只能走构造**（只有 `set_rows` / `set_on_sort` / `set_on_select`）。后果是在本仓深色面板里就是一张浅色斑块而结构上无从改色。**不登记缺口**：同一条判据在册的先例是本节末那条 7.52 就地更正——`MenuBar` 的下拉同样硬编码浅色、不随 `Theme`，当时的处置是「框架渲染但不随主题」而**不派框架**；且本件所需形态（三列表 + 冲突标注 + 延后角标）已由本仓的自绘行表承担（主题卡 / 16 格色板 / 回退链三段都是自绘，裁决 7.61 / 7.62），属裁决 7.13② 的「公共 API 可组合、留本仓」。文案侧另有一条同族事实：三件的标签都是 `std::string`（`DataColumn::label`、`TreeItem::label`、`ListView` 的 `items_`），**没有 i18n 查表路径**，故显示串一律由调用方给（与 G28 回货后 `settings_label()` 只留给收 `std::string` 入口那条同口径）。

12. **`Switch` 只有启用态的四档色可交，禁用态那一组硬编码浅灰**（同棒实测，裁决 **7.68③**）：`switch.h:396-399` 在 `!enabled_` 时把 active / inactive / thumb 一律**覆盖**成 `{176,176,180}` / `{210,210,214}` / `{240,240,242}`，而公共面的色 setter 只有 `set_active_color` / `set_inactive_color` / `set_thumb_color` / `set_border` 四件（裁决 7.57⑥ 那条自我更正推翻的正是「关态轨道色无 setter」，盲区是这一组禁用态）。**在深色界面上的后果是反的**：灰置档比可用档**更亮**——本仓交给关态轨道的是 `kControlBg{40,42,54}`，禁用档却是 `{210,210,214}`。**不登记缺口**，两条理由：① 本仓**不需要**禁用态开关。S10 与 S15① 拍的形态是「画控件、显示当前值、可改可落盘、行尾挂延后角标」，`apply_scope()` 把 `Absent ∧ Immediate` 折成 `PersistOnly`，故状态栏那十枚是**可用而只落盘**，暗色观感由那四件 setter 交出而不是走 `set_enabled(false)`；② 真要用禁用档时 `paint_track` / `paint_thumb` 是该文件自陈的 protected virtual 继承扩展点，应用侧子类覆写即属 7.13② 的组合形态（同口径先例：裁决 7.47 的 D8 用 `TextInput` 子类补 `Esc` 与失焦）。附带一条供后续任何用禁用档的地方参考的实测：禁用态 `on_pointer_event` 先置 `e.is_handled = true` 再 return，即**吞掉点击而不冒泡**，于是「点它不动」的证人只能判计数而不判链上有没有它（与裁决 7.62④ 那条「`Button` 未覆写命中入口、禁用态仍在链上」同族）。

13. **#117 的降级对话框回到 `au::Dialog`，但 `aurora::alert` / `confirm` 仍不可用**（同棒实测，裁决 **7.68④⑤**）：两处硬编码——`dialog.h:150` 的遮罩是 `p.fill_rect(bounds, Color(0, 0, 0, 128))` 且**无 setter**（半透黑遮罩在深色启动路径上正合适，故本仓不需要它可配，登记为限制）；`alert` / `confirm`（`dialog.h:211 / :235`）的按钮标签是字面量 `"OK"` / `"Yes"` / `"No"`，标题与正文参数又是 `const std::string &`，**整条链路没有 i18n 入口**，而 S13 拍的是「UI 按 `outcome` 枚举取本仓中文词条」，交进去就是一屏英文。故 #117 的形态是 `au::Dialog` + **本仓自建 content Node**：`Text` 交 `LocalizedString`（`text.h:236 resolved_text(ctx)` 走查表并随 `LocaleProvider` 取区域，与 G28 回货后的 `Button` 同源，故 G28 那条只挡按钮而不挡本件）、长列表包 `au::Scroll`（G26 / G27 回货后内容写 bounds 且把命中点按 `offset_y_` 折回内容坐标，于是 §6 第 8 条那句「作废」的组合形态**在对话框这一侧重新成立**）。另有一条只有读派发栈才现形的物理事实：**`Dialog::show()` 的模态焦点作用域在启动路径上取不到**——`current_focus_manager()` 由 `EventDispatcher::dispatch`（`dispatcher.cpp:185`）与窗口宿主（`window_host.cpp:218 / :254`）配对设置，**只在派发栈内有效**，故 `main` 里直接 `show()` 走的是该文件自陈的「无焦点管理器时降级为仅置位」分支，`push_scope` 不发生、Tab 焦点不关在框内；框架给「不在派发栈内发起动作」的文档化通道是 `resolve_focus_manager(Widget&)`（`event/focus.h:131` 起，沿 `layout_parent()` 上溯取或建按根缓存的兜底实例），#117 若要真模态须经它或把 `show()` 挪进首次派发 / 帧回调。**不登记缺口**（三条都在既有公共 API 的组合面内）；且「遮罩吸收点击」与「焦点作用域」是两件事：G26 回货那条 `on_hit_test_chain` 在遮罩区回 `{this}` 不依赖作用域，所以降级对话框即便不推作用域也不会点击穿透。

14. **浮层锚点没有「控件 → 窗口绝对盒」的公共入口，事件侧那一对坐标可用但它落在内容坐标系里，故本仓走过渡形态并已派框架**（读源结论 2026-10-06 A4 字体族浮层棒，裁决 **7.69③**；实现腿实测与 **G36** 登记见裁决 **7.70②③**，**该条原判「真缺口 0」随实测作废**；**该病灶已于同日回货闭合，见本条末段**）：`Widget` 公共面只有 `size()` / `paint_bounds()` / `focus_bounds()`，`Node::bounds()` 是父写入的**局部**盒；而 `paint_bounds()` 在离屏缓冲（`Scroll` 内容）里是缓冲帧读数——框架自己在三处写下这条限制（`widget.h` 的 `focus_bounds_` 注「离屏缓冲内的后代处于**内容坐标系**，其盒不等于屏幕坐标」、`a11y_tree.h` 的同款注、`scroll.h` 的「几何与命中契约」节），其自有 UIA / ATSPI 桥（`win32_ua.cpp` / `atspi_protocol.cpp`）亦直接取 `paint_bounds()` 而带同一限制，即框架自己也没解决「事后问一个控件要它的屏幕盒」。框架对同一问题的自解形态是**派发期把偏移透传下去**（G30 回货那条 `ancestor_offset`）而非事后查询，`command_palette.h` 的 `to_global(local, bounds)` 则是**私有静态**且只在自身绘制帧内用。**本棒走的公共路径**是派发器 `deliver_chain` 里那句 `e.local_position = global - it.origin`：控件在自己的 `on_pointer_event` 里按 `position − local_position` 即得**该控件的盒原点**（`it.origin` 与绘制原点逐位相等由 G31 回货保证，裁决 7.64②③④）。<br>**但那一读数是内容坐标而不是窗口坐标**（实现腿实测，裁决 7.70②；7.69③ 原文写作「自身的全局内容盒原点」，该句就地更正）：`Scroll` 的派发链给子的 `global.origin` 是「视口窗口原点 + 内容盒原点」而**不扣** `offset_y_`，故本件还须减掉行区当时的 `offset_y()`（公共面有这一个量）才落回窗口坐标，实测那一次差值恰等于它（修复前那帧 834 对 451，差 383）。`paint_bounds()` 是**第三个**坐标系，与本读数不可互推（同帧实测 748 对 826，差 78 dp）——`Scroll` 录制进离屏缓冲时传入的盒原点是 `-buffer_origin_y_`，而那个量公共面取不到。两条代价与一条禁止项如实登记：⑴ `Modifier::clickable` 的回调**不携带坐标**，公共面也没有带坐标的指针修饰钩子，故锚点必须由本仓的 `Button` 子类在 `on_pointer_event` 的 Press 分支自取（与 `BlurCommitText` 同档私有子类形态，属裁决 7.13② 的可组合面）；⑵ `au::Popup` 的 `on_layout` 按**松约束**测内容（max 取父 max 或 4096）而自身在常规流占零尺寸，故 20+ 档候选列须自带 `Scroll` 锁高，否则整叠溢出窗口——这是第 10 条那条 `Dropdown::panel_box` 限制在 `Popup` 形态下的对应物，`Popup` 侧的解法是本仓给内容包一层 `Scroll`，而不是改挂载点或换成自绘覆盖层；⑶ **不得**改用 `paint_bounds()` 做应用侧几何折算（G31 / G32 是同族病灶：应用侧自算几何终将分叉）。另有一条派发栈事实与本条同源而后果相反（7.68⑤ 那条）：`Popup::open_at` 只在 `current_focus_manager() != nullptr` 时压焦点作用域，而该上下文只在派发栈内有效，故**从按钮的 Press 回调里 `open_at` 恰好落在栈内**（Tab 焦点关在浮层内）；`Popup::close()` 自带 `open_` 守卫，未开时不弹栈，故面板经非派发路径程序化关闭也不会产生悬垂弹栈。<br>**G36 已于 2026-10-06 同日回货（Aurora `416b27bc`，裁决 **7.73**），上面 ⑴ 与「须减 `offset_y()`」那两处过渡形态按预诺一并撤除**：公共面新增 `Widget::window_bounds() -> std::optional<Rect>`（查询时沿 `layout_parent_` 现算、恒窗口逻辑 dp、不读绘制期缓存；父侧新增虚钩子 `scroll_content_offset` 只有 `Scroll` 覆写为 `{0, -offset_y_}`，故 `buffer_origin_y_` 不进这条算式），本仓的锚点因此是 `anchor->window_bounds()` 配 `size().height`，取不到即**不弹**而不是猜一个坐标，实现侧净减 **47 行**、零新增算式，`AnchorButton` 子类与面板自持的 `row_area_` 全仓无残留。**回货判据② 被该仓自己实测否证并就地改口**：`Scroll` 后代上的 `HitNode.origin` 并非窗口坐标（对照读数「真窗口位 60 / `window_bounds()` 60 / `HitNode.origin.y` 260」），缺 `offset_y_` 这一项是**活的派发缺陷**、已记进该仓 `05-event-navigation.md` 待另开提案，与本条上面那句实测同源。故本稿的证人写法随之确定为：出账判据以**派发落点**（`e.position` 本身即窗口坐标，即 `Harness::reachable_box()` 量出来的那个框）为基准与 `window_bounds()` 逐位相符，另留一条「`paint_bounds()` 与该读数在滚动偏移非零时**必然不相当**」的防回退钉子；本仓**不**写复述框架私有算式的判据（AGENTS.md §5 第 2 条）。

**一处对既有在册实测结论的就地更正**（裁决 7.52）：本仓 2026-10-02 在册的「框架 `Modifier::context_menu` 与 `MenuItem` 只有状态模型、**没有渲染与点击派发**」这半句不成立——`MenuItem` 是**有**渲染与点击派发的，载体是 `widget/menu_bar.h` 的下拉：`on_paint` 逐项画分隔线 / 标签 / 勾选标记 / 置灰色，`on_pointer_event` 的 Press 分支按等分行高折出序号、命中非分隔且 `enabled` 的项即调 `item.on_click()`，其 `wants_click()` 恒 `true`。须更正的是**两处限定**：① 派发只发生在 `MenuBar` 自己那块下拉矩形内（`dropdown_bounds()` 相对本控件原点），不是任意位置的上下文菜单，框架没有后者这件控件；② 那条下拉的色值是**硬编码浅色**（白底 `Color(255,255,255,255)`、正文 `30,30,30`、disabled `170,170,170`），**不随 `Theme` / `ThemeScope`**，故 7.41③ 的置灰档在深色界面上本就不可用。据此，`Modifier::context_menu` / `ContextMenuNode` 那一腿**确实**只有模型（存 items + `open_at` / `is_open` / `position`，全仓无 widget 侧渲染者；`system_tray_win32.cpp` 的 `show_context_menu` 是托盘自己的 Win32 原生菜单，不经控件树），而本仓右键菜单取 `au::Popup` + 一列 `au::Button` 的形态**不变**，只是理由从「框架不渲染不派发」改为「框架渲染但不随主题、且没有任意位置的弹出件」。回写落点：`codespec/SPECIFICATIONS.md` 附录 A.1 的菜单那一行与裁决 7.41③、`codespec/ARCHITECTURE.md` §9.2、`AGENTS.md` §6 各加就地更正，`codespec/ARCHITECTURE.md` §11.1 另补两条本稿实测的边界（chrome 色源须由本仓在装配阶段注入 `ThemeScope`、色值不经配置往返故面板不得有 alpha 位）；`codespec/CHANGELOG.md` 的历史条目按「旧编号旧条款原文保留」不改，只在 v0.49 条目里记这条更正。
另一条复核**不变**：`OverlayHost::handle_outside_click()` 在 Aurora 全仓**没有生产调用点**（只有旧备份命中），故裁决 7.41③ 的「外部点击由本仓在 Press 分支自驱」继续成立。

## 8 验收判据（拍板并实现后）

- **纯逻辑**：面板本体的可脱界面断言面原先是**三件**纯逻辑前置——① schema ↔ 控件的**反向核对件**（每一键给出页 / 控件类型 / 取值域 / 生效档位，且判据是「`config::Settings` 里没有的键不出现在表里，表里没有的键必须显式列为撤销项」，即 §2 与 §3 的可执行形态）**〔已落 2026-10-04：`ui::settings_catalog()` / `ui::find_settings_control()`（`include/borealis/ui/settings_catalog.h` + `src/ui/settings_catalog.cpp`）+ `utest_settings_catalog` 八例。落地时的三点处置：基准取 `Store::replace(全量非默认 Settings)` 真正写出的 JSON 剥掉 `schema_version` 与框架 `__aurora_preference_meta__` 后的叶子键集，故判据① 的双向都由表自身驱动（表里新增一键，探针自动覆盖它）；「消费方现状」与「生效档位」做成**两个正交字段**（`ConsumerStatus` × `EffectLevel`）而非本稿 §2 表头那一列四值档位，依据是 §4 B3-a 的原句「两条标签不冲突」，如此才表达得出 `terminal.encoding` 的「延后 + 下次会话」；**撤销项不做成表里的行**——§3 那四处「图上画了、schema 没有键」的控件本就不在叶子键集内，双向比对天然把它们排除，再列一份撤销清单就是第二个需要人维护的名单，其判据改由 §3 的文本与本表的键集共同守；**一条判据边界如实登记**：取值域那几列是**单向**可证的（表比装载侧宽 → 面板给出的值存不回去，探针写进去必留 `rejected_keys` 痕迹，抓得到；表比装载侧窄 → 只是面板少画一个合法选项，装载侧不会为此报错，而装载侧的白名单是 `store.cpp` 的文件内私有表、公共面没有「列出某键全部合法名」的入口，故本件无从反向枚举）。少画选项的后果由人在评审时看到并补表，不由本件伪造一个抓不到的判据〕**；② HEX 文本 ↔ `ui::RgbaColor` 的解析与格式化（大小写不敏感、位数不足 / 前缀缺失、非法字符三类，且**与装载侧同一条式子**——`#RRGGBBAA` 与 `rgb()` 式一律判非法）**〔已落 2026-10-04：`ui::color_to_hex` / `ui::color_from_hex` + `utest_color_text` 九例，`src/config/store.cpp` 的三份私有实现已删除并由该件消费〕**；③ 「哪些键改了、要不要落盘、生效档位」的表单状态机（含 S14 的提交时机）**〔已落 2026-10-04：`ui::SettingsForm` / `ui::FormValue` / `ui::apply_scope()`（`include/borealis/ui/settings_form.h` + `src/ui/settings_form.cpp`）+ `utest_settings_form` 十三例。落地时的六点处置：**
  - **键一律用落盘点号路径指代，本头不含 Aurora 也不含 `config` 类型**（与 ① 同一条模块环理由），值用本件自己的 `FormValue`（八档形态族与 `ValueDomain` 一一对应），行向 `ui::settings_catalog()` 现查——面板、本件、反向核对件三者共用同一套地址，于是「面板画的控件」与「表单里可提交的键」不可能各说一套。`config::Settings` 的成员搬进搬出不归本件，落在本稿 §8 的 ④ 那件搬运件，**据此一条边界如实登记**：本件守不到「两个同域成员互换」（`appearance.font_line_height` 与 `appearance.font_letter_spacing_dp` 同为实数），那条事实的证人自 2026-10-04 起是 ④ 的取侧与写侧逐键判据（裁决 7.54），而不再只是下面集成那条像素判据。
  - **校验式不新造第三条**（S14 的硬约束）：区间与白名单逐键取自 ① 那张表（其区间已按判据① 逐键交回装载侧复核），色值文本走 ② 那件的 `ui::color_from_hex`。故 `#12ab34ff` 这类「面板接受而存不回去」的形态在表单同样判非法，「面板抄宽了区间」在本件也不可能有第二份数据可抄。
  - **「未配」是一次显式动作**（`commit_unset_color`）而不是空串：裁决 7.27③ 区分「显式 `null`＝用户点名的未配」与「畸形值＝回落并留痕」，空串属后者；A2-b 要的「未配」与「配成黑色」可区分，在值上就兑现为 `std::optional<RgbaColor>` 的空值与 `RgbaColor{}` 之别。只有两行可收（`OptionalHexInput`），必填色槽收到未配回 `UnsetNotAllowed`。
  - **S14 的提交时机在接口形态上兑现**：文本入口只有 `commit_text` 一条，且按**控件形态**把关——只放行 HEX / 自由文本 / 步进三形态，下拉与开关的候选由控件给出、走 `commit_value`。面板若在逐字符变化处就调本入口，半截输入（`#12`）会被判非法而**值一字不动**，于是「失焦或 Enter 才提交」不是约定而是有可判定形态的接缝；校验不过时本件只回一个 `CommitIssue` 枚举，中文词条由 `StringTable` 按该枚举取（裁决 7.25⑬），本件不产文案也不产 ASCII 诊断串。
  - **生效档位折成两个动作而非四值**：`apply_scope()` 只在「已接线 ∧ 即时」给 `PersistAndApplyNow`，其余三档一律 `PersistOnly`。依据是本稿 §4 B3-a 的原句「两条标签不冲突」——没有消费方就没有可广播的对象，故 `Absent ∧ Immediate`（状态栏那十个开关）与 `Wired ∧ NextSession`（`terminal.scrollback_limit` 等三条构造期取用）给出的都是「只落盘」。
  - **脏标记按值而非按提交次数**：`is_dirty()` 比的是「当前值 vs 最后一次成功落盘的那份」，故改了又改回来既不落盘也不广播；`note_persisted()` 只在 `Store::replace()` 返回空值后调，它拒绝落盘时不调用，脏标记因此留着而面板不谎报已存。装载还做一次结构核对（表里有值没给、给了但形态族不符、路径不在表里 → 三张名单），面板据此少画控件而不是画一个存不回去的控件。〕**
④ **面板本体开工时补出的第四件前置**：`config::Settings` ↔ `ui::FormValue` 的**搬运件**——①②③ 三件之外多出的一件：表单件按点号路径放值、不认识成员，而面板要的是「装载一份配置」与「写回一份配置」两个具体动作；这件**只能落在 config 侧**（`config/settings.h` 已 include `ui/palette.h`，反向 include 即 `config ⇄ ui` 模块环，与 ① 同一条理由，裁决 7.32① / 7.41① 同因）**〔已落 2026-10-04：`config::form_entries()` / `config::apply_form()`（`include/borealis/config/form_transfer.h` + `src/config/form_transfer.cpp`）+ `utest_form_transfer` 十例。落地时的五点处置：**
  - **一行 = 一个键的两个方向**（本件唯一的防分叉手段）：`Binding{key, get, set}` 58 行按 ① 那张表的次序把「取」与「写」并列在同一行，键 ↔ 成员的对应因此只写一次，两个方向不可能各指一个成员。**不复检取值域**（裁决 7.46② 的分工：区间与白名单由装载侧与 ③ 那件把守），本件只折算类型，形态不合的值不改基线；③ 没给值的键（缺键与错型键，见 `FormLoadReport`）写回时**保留基线**——「面板少画一个控件」不等于「把该项设置抹掉」。
  - **枚举落盘名从 `store.cpp` 的匿名命名空间迁出**成 `src/config/schema_names.h`，装载侧与本件共用一张表；该头刻意**不进 `include/borealis/`**——公共头上开一份「枚举名表」等于把它变成第二份契约，而契约是 `settings.h` 的字段与落盘 JSON。本表与 ① 那些下拉行 `choices` 的等价不由本头自证，由下面第三条的跨件判据逐键验。
  - **判据按方向配齐三件，另两条跨件**：取侧逐键字面量（一份逐键互异的配置摊出 58 个显式预期，`font_line_height` 与 `font_letter_spacing_dp` 各取互异值，故「两个同域成员互换」在此现形——上面 ③ 登记的那条边界由此闭合）、写侧逐键唯一移动（只提交一键，其余 57 键的取值必须一字不动）、**布尔两族直接读写 `Settings` 成员名**（布尔只有两档值，前两件对「整行互换的两枚同值布尔」结构上抓不到，故 20 行探针表逐键点名；这不是凑数，是那类错误唯一的观测通道）；跨件两条是「下拉候选经**配置文件**往返」（本件与 `store.cpp` 共用那张名表，拼写漂移在读回时现形，并同时转红 ① 的白名单例）与「未配色槽往返成未配而不是黑色」（裁决 7.27③ 的 A2-b）。
  - **八条变异注入各有转红证人**（每次重链前删 `build/**/*.ilk`）：取侧互换两个实数行（四例红，而 `utest_settings_form` **全绿**——正是本件补上的那条边界）／写侧互换（回读三例红）／布尔整对互换而键不变（取侧逐键例 + 两族各一例红）／删一行绑定（覆盖关系例红并点名 `terminal.word_delimiters`，另三例同红）／落盘名漂移 `osc_wins`→`osc`（本套件三例 + `utest_settings_catalog` 的白名单例，跨套件证明名表单源）／色板取侧反序（四例红）／未配取侧回落黑色（三例红）／未配写侧折成黑色（两例红）。非 e2e 通道 **36 项全绿**。**本棒未复跑吞吐门禁**：新增 TU 不在任何绘制与布局路径上（只在面板打开时被读写一次），算式零改动。
  - **一条用例写法教训**：行数判据必须先 `AURORA_TEST_REQUIRE_EQ` 再逐格按序比——`AURORA_TEST_CHECK_EQ` 不终止用例，删一行绑定之后的 `entries[index]` 就是越界读，变异读数会成一次崩溃而不是一个红用例（首轮实测如此）。

  **面板行区容器换形与一条坐标陷阱已落 2026-10-05**（`src/ui/settings_panel.cpp` + `tests/integration/itest_settings_panel.cpp`，裁决 **7.60**）：行区由 `LazyList` 改 `Scroll` + `Column`（理由与代价见 §6 第 8 条末），于是「内容子节点 bounds 是**内容坐标**」这条框架自陈的不对称第一次进入本仓判据（`Scroll` 命中时把局部点**加上** `offset_y_` 换算回去，而 `LazyList` / `GridView` 写的是**视口坐标** `index × extent − offset`）。用例侧因此把每一处探针改成**按真实派发量**窗口坐标（`Harness::reachable_box`，1 dp 步进），`paint_bounds()` 之后只用于取尺寸。**两条判据写法教训随本条入册**：① 松判据会被坐标错误静默吞掉——把取色点退回 `paint_bounds().origin` 做变异注入，全套 20 例**仍全绿**，因为「chrome 不亮」这条判据线在卡片底、导航列、遮罩上都成立；故「取色点归该控件所有」升级为取色的**前提**（先按派发链确认归属再读像素），加固后同一条注入恰在该例转红。**推论：给面板新增像素判据时，取点来源必须由派发链自证，不得由 bounds 推算。**② 挑样启发不是判据——`find_first` 的 `room_below_dp`（「否则测的是视口裁剪而不是派发」那句注释）把余量算式退回内容坐标**同样全绿**，因它只是「扫描时挑哪一行」的启发；那句反空转前提已改为写进两条下拉用例正文的显式断言（探点在视口之内）。验收：`itest_settings_panel` 19 → **20 例**，非 e2e 通道维持 **37 项全绿**；七条变异注入里**四条转红**（开关轨道退浅色 / `ScrollProps::step = 0` / G30 探点 `+12→+4` / G29 探点退回自身盒内），**三条等价并如实登记**（去掉行区 `Scroll` 的 `.expand()`——框架「容器自身取父约束给出的视口尺寸」，该 modifier 在几何上本不承重；以及上面①②那两条），按裁决 7.49⑥ 不伪造证人。
