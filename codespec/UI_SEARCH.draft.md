## 0 本稿的性质：目标态（D1~D8 于 2026-10-07 自拍，结论见 §3 行末）

- 图上每一格按**目标网格**逐格落位（与 `codespec/RENDER_UI.draft.md` §0、`codespec/UI_SELECTION.draft.md` §0 同一套矢量法），不是任何一次真实渲染的截图——出本稿时本仓还没有浮层绘制代码，画不出「现状」。**该句随裁决 7.81 已过期**（浮层本体已落，本稿不重出图）。
- **本稿不新增任何配置键**：命中色取既有 16 色格的 `basic[11]`（§3 D2），因此设置面板的反向核对表、色板格数与「自定义」角标的判定档位一律不变（那三处各是五档 palette 槽，多一个槽就是多一处跨件判据，见裁决 7.61 的角标段）。需求原文没有「命中色可配」这一项，本稿不自造（AGENTS.md §4.1 第 1 条）。
- 本稿依赖的既有事实：五层绘制序列与「选中格的底色在色带层内替换、不另立一层」（架构 §9.2，裁决 7.38① D1① / D4①）；`ui::layout_row` 目前**只收一段** `RowSpan`（`include/borealis/ui/cell_layout.h:183`；**该句随裁决 7.80 过期**——命中区间入参与三层底色折叠已落地，形态见彼条①）；场景根是 `au::OverlayHost`（`src/main.cpp:178`）；`au::Popup` / `au::TextInput` / `au::Button` / `au::Canvas` 均在框架公共 API 上（面板五处区段与右键菜单已是四次先例）。
- **框架缺口 0**：本稿没有一处需要框架代劳。锚点取裁决 7.73 回货的 `Widget::window_bounds()`；浮层的「点浮层外即关」按裁决 7.41③ / 7.70③ 由本仓在 Press 分支自驱；开关 chip 用 `Button` 的选中态底色自绘，不用框架 `Switch`（后者在深色面板上的禁用档色值硬编码浅色，裁决 7.68② 实测）。**该「缺口 0」的射程随裁决 7.81 收窄**：实现腿实测登记 **G37**（`Popup` 内容的 `window_bounds()` 取不到锚点平移，见附录 A.2 / 裁决 7.81②）——本稿的生产路径不受影响（锚点取的是焦点 pane 的视口盒而非 `Popup` 内的控件），受影响的只有集成用例对 `Popup` 内容的事后几何取点，本仓已走真实命中链规避。

## 2 逐面板判据

**A. 展开态（A1 有匹配 / A2 空输入）**

- A1-a：浮层是**单行条**，经场景根 `au::OverlayHost` 承载，锚在**焦点 pane 的内容盒右上角**，距右缘与上缘各 8 dp；pane 宽度不足时按 E 面板降级，但右缘与上缘的 8 dp 内缩量不变。
- A1-b：条内自左至右恰为七件：**输入框（可收缩）· 计数 · 「区分大小写」chip · 「正则」chip · 「上一个」· 「下一个」· 「关闭」**。件间距 8 dp，条内左右内边距各 8 dp。
- A1-c：**浮层是宿主叠在视口之上的独立层**（架构 §9.2 末条），按目标网格覆盖条下方那一段——`[8 dp, 52 dp)` 即第 1 行下 14 dp、第 2 行整行、第 3 行上 8 dp。被盖的行**照旧参与绘制与高亮**（终端不是被暂停了，是在收新输出），判据因此不是「被盖区画了什么」而是两条：**条内不出现终端字形**（无头帧里条矩形是浮层自己的像素），以及**关闭浮层后那三行的内容与高亮逐位回到未遮挡态**。
- A1-d：两枚 chip 的**可视标签是 ASCII 符号** `Aa` 与 `.*`，其**无障碍标签**是中文词条（`search.toggle_case` ＝「区分大小写」、`search.toggle_regex` ＝「正则表达式」）。判据形态：符号档在 44 dp 单行内恰占 40 dp，中文四字标签需要约 56 dp，而七件按符号档就需要 **480 dp 内容宽**（E1-a），已是最小合法 pane（228 dp，E3-b）的 **2.1 倍**——**符号是宽度算式的结果，不是省事**（代价见 §3 D1）。
- A1-e：当前命中的那一格用**全色**，其余命中用各半混合；两者是同一色相的两档强度，**不引入第三种色**（于是「哪一格是当前位」在只有一格命中时仍然可判，见 C 面板）。
- A1-f：**命中高亮不随失焦降级**——这与选区相反（`codespec/UI_SELECTION.draft.md` 的 D3① 取的是各半混合）。理由是一条时序：浮层一打开，键盘焦点就归输入框，视口**必然**处于失焦态；若命中也跟着降级，「正在搜的这一次」反而是画面最弱的一档，而降级本身的用途（切走窗口后找回旧选区在何处）在搜索里没有对应场景。代价：同一次画面上会同时存在「降级后的选区色」与「全强度的命中色」，两者相撞时仍按 C1-a 的序走（选中盖命中），故层序判据与失焦判据是两条独立的断言。
- A1-g：两枚 chip 的**初值与 `ui::SearchQuery` 的字段缺省逐字同档**——大小写不敏感、非正则。开界面时不重述一遍缺省值，故「界面初值 ≠ 纯逻辑缺省」这类分叉结构上不成立。
- A1-h：**条体 chrome 取本仓缺省的深色档，且不随终端主题联动**——与设置面板浮层是同一条 S5 口径（裁决 7.52），条内文本、输入框底、chip 选中档一律从那张缺省 chrome 表取。理由是浮层的位置在正文之上而非正文之内：浅色主题下「浅色条压浅色正文」会让条与正文的边界只剩一条描边，而本件的判据（A1-c 的「条内不出现终端字形」）要的就是那道边界。代价：深色条叠在 dracula 正文上只差一档亮度，故遮挡边界在图上须靠描边而不是底色差；本稿不新增配置键（§0 第 2 条）。
- A2-a：输入框为空时**不发扫描**（`ui::search` 的空串即此口径），计数槽显示占位「—」而不是「0」，条内不出现任何高亮。
- A2-b：空输入下「上一个 / 下一个」两枚按钮**灰置**（`MenuItem.enabled` 同一条置灰纪律，裁决 7.41③ F-b：置灰而不是点击后静默失败），「关闭」不灰。

**B. 计数槽的六种形态（B0~B5，逐字判据）**

- B0 空查询：`—`（不是 `0/0`，也不是空——空槽读起来像控件坏了；见 A2-a）。
- B1 正常：`当前序号/总数`（例 `2/7`），右对齐，序号**从 1 起**（界面上从 0 起是给用户看的错误）。
- B2 有查询但零匹配：`无匹配`（不是 `0/0`——`0/0` 读起来像「还有下一个」）。
- B3 触到 `ui::kMaxSearchMatches`：`10000+`（裁决 7.78④ 明写「计数是下限，不得谎报总数」；界面上的 `+` 就是那条禁止谎报的兑现形态）。当前序号仍照 B1 显示。
- B4 正则编译失败：`表达式非法`，且**高亮保留上一份结果**、游标不重置（`ui::search` 返回 `std::nullopt` 当且仅当这一档，故界面层能区分「表达式错」与「搜不到」，这正是 B2 与 B4 必须分成两句的原因）。
- B5 「还没扫」：`按 Enter 应用`（正则档打字之后、提交之前）／`按 Enter 搜索`（重开浮层而旧文本非空）。两句是同一处物理事实的两个现场：**此刻画面上的高亮属于上一份结果或根本没有结果，而输入框里的文本已经不是它**。这条形态是 §3 D4 取「正则档只在提交时扫」的直接代价——少了它，用户会以为画面上的黄格就是刚打的那串。此时高亮一律**保留上一份**（与 B4 同一条），因为清空它等于把「等一下按 Enter」变成「搜不到」。

**C. 层叠与同格相撞（C1 选区 / C2 光标 / C3 行尾）**

- C1-a：一格既是命中又是选中时，**选中色胜出**——裁决 7.38① D4 已提前拍死这条序，本稿照办；于是选中一段命中文本时那几格仍是选区色，用户看得出「我正在选的是刚才搜到的那段」。
- C1-b：命中的换底**只换底色不换前景笔形**，与选区同一条规则（`ui::layout_row` 的 `min_contrast` 重合成对两档命中色各跑一次；`basic[11]` 全色压在 `default_foreground` 上必然低于阈值 4.5，故那一格会**自动转成深色前景**，这是既有合成的产物而不是本稿新写的分支）。
- C2-a：光标层在两者之上；块形光标压在命中格上时，三段式第三段的重画底取**该格的命中色**（与裁决 7.40⑧ 给选区的那条同一条算式，只是入参换成命中底色）。
- C2-b：**当前命中格的整格高亮不得被光标块「挖空」**——判据是像素层的「该格两帧差分后仍非 `default_background`」。
- C3-a：命中区间恒为**整格对齐的闭开区间**（`ui::SearchMatches` 的产物即此），双宽字符要么整字符亮要么不亮，不出现半个字有色。
- C3-b：**行尾连续空白填充不算内容**（裁决 7.78⑦），故查询串里带尾随空格时不会在每行行尾亮出一片——这条在图上是「第 40 列之后不亮」。

**D. 跳转的落位（D1 可见 / D2 需滚动）**

- D1-a：Enter 前进、Shift+Enter 后退，**首尾相连**（`SearchMatches::advance` 的既有口径，裁决 7.78③）。
- D1-b：目标行**已在可见窗内**时画面**完全不动**（不重新居中），只把该格升到全色档、上一格退回各半档。
- D2-a：目标行**不在可见窗内**时，把该行滚到视口**竖直居中**（钳在 `[0, max_offset]` 内），回看位置随之真改变（即这是用户可见的一次滚动，不是临时偏移）。
- D2-b：居中算式只有一个输入：目标存储行 − `window_top()`。判据是「跳回看区深处的一条匹配后，该行落在中间那一格，且上下各有 `⌊rows/2⌋` 行上下文」。
- D2-c：**关闭浮层不清回看位置**（只清匹配表与高亮），否则用户从报错行被踢回提示符，见 §3 D7。

**E. 宽度降级三档（E1 常规 / E2 紧凑 / E3 两行）**

- E1-a：条宽 `W = clamp(pane宽 − 16 dp, 本面板的下限, 560 dp)`（A1-a 的右缘 8 dp 内缩 + 左缘至少留 8 dp）。三档的门槛一律由**内容宽**（`W − 16 dp`，即 A1-b 的条内左右内边距各 8 dp）反推，**内容宽与条宽不得混用**——这是本稿初稿写错过的地方。常规档：固定件之和 ＝ 计数 64 + 两枚 chip 80 + 两枚带文字按钮 128 + 关闭 40 ＝ **312 dp**，加六段间距 48 dp，再加输入框下限 120 dp ⇒ 内容宽 **480 dp** ⇒ **条宽 496 dp ⇒ pane 宽 ≥ 512 dp**。
- E2-a：pane 宽 `[456, 512) dp` 时，两枚跳转按钮**去文字**改 40 dp 图标档（`↑` / `↓`），计数槽收到 56 dp，固定件之和 256 dp，加间距与输入框下限 ⇒ 内容宽 **424 dp** ⇒ **条宽 440 dp ⇒ pane 宽 ≥ 456 dp**。文字只是鼠标可达性的补充，Enter / Shift+Enter 是同一功能的需求原文写法。
- E3-a：pane 宽 `[200, 456) dp` 时改**两行**（条高 66 dp）：第一行「输入框（下限 120 dp）+ 关闭」＝内容宽 168 dp，第二行「计数 + 两枚 chip」＝内容宽 144 dp，故**条宽 184 dp ⇒ pane 宽 ≥ 200 dp**。此时**跳转按钮不再出现**——第二行若保留它们就需要 `56 + 40×4 + 三段间距 24 = 248 dp`，而本仓最小合法 pane（228 dp，见 E3-b）能给的内容宽只有 `228 − 16 − 16 = 196 dp`，算术上到不了。
- E3-b：**pane 宽 < 200 dp 的那一档结构上不存在**，故本面板只有三档、无第四档：本仓最小合法 pane 由 `max(20 列 × 格宽, 3 行 × 格高) + 两格内边距` 现算（裁决 7.47⑥ / 7.49⑤），11 dp 格宽下即 **228 dp**，而 228 ≥ 200。代价随之如实登记并归真机走查：**最窄可达的 pane 上跳转只剩键盘两档**，纯指针（触屏 / 无键盘）用户在该档无法前后跳——这是一条**能被算出来的边界**而不是「大概很窄」。

**F. 打开、关闭与键位归属（F1~F3）**

- F1-a：打开入口是命令层的 `search.open` + `Ctrl+F`（与 `settings.open` + `Ctrl+,` 同形态，裁决 7.56）；`Ctrl+F` **不进会话**（快捷键层在控件消费之前拦截，架构 §9.6 与裁决 7.51③ 的 (a) 腿），故运行 vim 时按 `Ctrl-F` 是本仓的搜索而不是 vim 的整屏翻页——这条需求原文就写死了，代价见 §3 D8。
- F1-b：`Ctrl+F` 不在本仓 12 条分屏保留位内（`ui::workspace_key_bindings()`，裁决 7.72），故快捷键只读表上该行**不标冲突**。
- F1-c：**再次打开时文本与两档逐字保留，但不自动重扫**（浮层懒建一次并常驻、之后只 `open_at` / `close`，与右键菜单同一条形态，裁决 7.41③）。不重扫的理由是一条成本而非手感：保留下来的旧文本若正是那枚宽匹配式，重开即扫就是把实测 **1623.5 ms**（100,000 行 × 80 列，裁决 7.78①）挂在一个用户没有任何动作的帧上。于是重开的那一帧走 B5 的 `按 Enter 搜索`。
- F2-a：关闭走四种——点「关闭」/ Enter 无输入时不关 / `Escape` / 点浮层外。其中 `Escape` 的登记按裁决 7.56 S2 的纪律：**打开时登记 `Global`，关闭时解绑**，留着就会静默吞掉发往会话的 `Esc`。
- F2-b：浮层可命中即认领，指针落在条内**不推进选区**（祖先收不到该点击，架构 §9.2 的 `is_handled` 短路），故条内的文本选择与拖拽一律归框架控件自己。
- F3-a：打开浮层**不改变**焦点 pane 的模型焦点、不改分屏布局、不触发 `Session::resize`；输入框夺走键盘焦点是这一次打开唯一的焦点变化（`apply_appearance` 那两条运行期入口与本件无关，裁决 7.53）。

## 3 决策点（自拍：全取建议项，逐条理由与代价见 §0 与本条行末）

| # | 议题 | 选项 | 影响面 |
|:---|:---|:---|:---|
| **D1** | 浮层形态与落位 | ① **焦点 pane 内容区右上的单行条**（44 dp 高，宽随 pane 降级）〔建议〕；② 整窗顶部居中的两行浮窗；③ 复用设置面板那种全屏浮层 | ① 搜索是「边看边跳」的即时操作，不能挡住整屏，也不能让分屏态下的另一个 pane 变瞎；②③ 都遮正文且② 在多 pane 时归属不明。代价：单行宽度算式逼出 E 的三档降级，chip 只能上符号（A1-d） |
| **D2** | 命中色来源 | ① **复用既有 `basic[11]`**，两档强度（全色 / `mix_half`）〔建议〕；② 主题表新增 `search` 槽 + 配置键 + 面板第 17 格；③ 直接用选区色 | ① 零新增配置，故反向核对表、`form_transfer`、色板区段、「自定义」角标四处都不动，且需求原文未要求可配；② 是五处跨件成本 + 一条新的往返判据，换来的是一次需求没问的可配性（违最小意图 diff）；③ 让「当前选中」与「当前命中」在同一个格子上撞色，C1-a 的层序就失去可观测性。代价：`basic[11]` 与光标色在个别主题上同值时，光标落在命中格上只能靠 C2-b 的「非底色」判据而不是色差 |

| **D8** | 打开入口与键位 | ① **命令层 `search.open` + `Ctrl+F`**（快捷键层独占，不进会话）〔建议〕；② 只在焦点 pane 的 `on_key_event` 里就地拦（7.47② 那种前置过滤）；③ 另配 `Alt+F3` 之类避让 vim 的组合 | ① 与 `settings.open` 同形态、且被快捷键只读表自动列出来；② 在分屏态下只有焦点 pane 能开，而① 是全窗口级。代价：**`Ctrl+F` 从会话手里拿走了**，vim 用户因此失去该键的整屏翻页——这是需求原文写的键，本稿不改判，只登记为真机走查项；另 `utest_shortcuts_table` 的保留位比对须确认该组合与 12 条分屏键位无撞（实测无） |

## 4 与现状的差距 → 实现须达到的条目

1. **绘制侧的入参形态**：`ui::layout_row(row, spec, const RowSpan &selection, const RgbaColor &selected_background)`（`include/borealis/ui/cell_layout.h:183`）只收**一段**选中区间；命中是「每行 0~N 段、且两档强度」，故须新增一个「本行命中区间列表 + 当前命中那一段 + 两档底色」的入参形态，并保证层序「命中 → 选中」（C1-a）在切 run 之前发生——run 按样式全等合并（裁决 7.23②），底色不同即断 run，故三档底色（未命中 / 命中 / 选中）会在一条边界上把 run 多切一刀。**已随裁决 7.80 落完**（`ui::RowBands` + `ui::background_at`）。
2. **每帧的区间表折算**：匹配表的坐标是**存储行序**（`include/borealis/ui/search.h` 头注），可见窗是另一档起点，二者换算仍只有 `session::ScreenMirror::window_top()` 一个量（裁决 7.40② 为选区立的同一条）。新输出把顶边推走时，`SearchMatches::translate_rows(rows_up)` 要在每帧吃两次 `dropped_lines()` 读数之差——与选区的折算共用同一次快照，**不新增锁**（裁决 7.78③）。逐行命中列表按可见行过滤，上限档的表（10,000 条 ≈ 240 KB）不得整份拷进帧里（`spans()` 给的是视图而非快照，正是为此）。**已随裁决 7.79 / 7.80 落完**。
3. **视口侧的扫描接缝**：`ui::search` 收 `grid::Storage`，而权威网格只在会话锁内可及；沿用裁决 7.40① 给复制腿改判的那条路径——在既有 `Session::read` 短临界区内一次扫完并把结果搬出锁外，界面层不新开线程、不做网格快照（裁决 7.78⑥ 的执行侧）。**已随裁决 7.79 落完**。
4. **程序化滚动入口**：条目 D2/D6 需要「把存储行 X 滚进可见窗且尽量居中」的写入口，现无（只有 `on_scroll` 的滚轮驱动与 `scrollback_rows_from_bottom()` 的读数）。**已随裁决 7.80 落完**（`TerminalView::scroll_row_into_view`，窗内不动而窗外居中）。
5. **浮层本体**：`src/ui/search_overlay.{h,cpp}`（**第五个**触达 `au::Painter` / `au::Widget` 的 TU，私有头形态同裁决 D1①）＋ 视口侧的持有与开关两处；打开入口 `search.open` + `Ctrl+F` 在装配层注册，`Escape` 的登记与解绑按 F2-a。**已随裁决 7.81 落完**。
6. **词条**：`search.placeholder` / `search.count_none` / `search.count_cap` / `search.count_invalid` / `search.pending_enter` / `search.reopen_hint` / `search.toggle_case` / `search.toggle_regex` / `search.prev` / `search.next` / `search.close` 进本仓词条表（上屏文案属 AGENTS.md §4.3 第 14 条的 `CJK-LITERAL: 上屏文案` 例外），chip 上的 `Aa` / `.*` 与按钮的 `↑` / `↓` 是符号而非文案、不进表，但两档各自的**无障碍标签**进表（裁决 7.61 那条「卡名逐字取存储键」之外的另一形态：符号在屏上、中文名在树里）。**已随裁决 7.81 落完**，且差额入册：实际 12 条——另补 `search.action.open`（F1-a 的命令标题，不在上面十一条之内）。

## 5 验收判据（拍板并实现后）

- **纯逻辑**（已随 `ui::search` 落完，本稿不重述）：区间整格对齐、行尾填充不算内容、零宽匹配不产区间、上限截断、`advance` 首尾相连、`translate_rows` 逐条丢弃与游标随表走——见 `tests/unit/utest_search.cpp`。
- **像素**（`tests/integration/itest_render_viewport.cpp` 通道，`HeadlessSurface` RGBA8）：
  - 两帧差分断三件事——**命中的每格变为各半档**、**当前命中格变为全色档**、**未命中且未选中的格不受影响**；再断 C1-a（同格相撞时读数＝选区色而非命中色）与 C2-b（块形光标压在命中格上时该格仍非底色）。
  - 前景那条走既有 `min_contrast` 路径，故断「全色档那一格的前景与 `default_foreground` 不同」而不是自算一个目标值（裁决 7.26① 的阈值 4.5 是同一条判据的真值源）。
  - **一条判据边界照搬 UI_SELECTION §5 的实测订正**（裁决 7.40⑨）：按边界重切 run 会让同 run 内后续字形的亚像素覆盖改变，故「未选格逐位不变」只对**无字形**格成立；带字形的未命中格改断「该格带色回到 `default_background`」。
- **交互 / 集成**（`tests/integration/itest_search_overlay.cpp`，真指针派发 + `au::OverlayHost`）：打开即得焦点且不向会话发出任何字节；打字→置脏→一帧内出现高亮且**一轮只扫一次**（以扫描计数为据）；正则档打字不扫、Enter 才扫；四种关闭各一条；`Escape` 关闭后**该键位已解绑**（判据是「同一帧再按 Escape 时被会话收到」，否则 S2 那条静默吞键的病灶无人守）；B3 触顶形态；B4 保留旧表；E 三档降级各一条（断控件盒宽与条高）；D2 的居中落位；D7 的「关高亮不关回看位置」。**已随裁决 7.81 落完**（十五条集成见证；其中「四种关闭」落成三条真路径——点「关闭」/ `Escape` / 点浮层外——并附一条 `Enter` 恒不关的负向断言，见裁决 7.81⑥）。
- **性能**：判据在基准与门禁，不在测试（AGENTS.md §4.4 第 21 条）——`tools/bench/render_throughput.cpp` 第四场景 + `tools/check/perf_baseline.json` 的 **B-8**（绝对线 200 ms、相对线 10%、三次独立进程中位、`build_config` 与 `search_fixture` 双硬判，裁决 7.78⑤）。界面腿**不**另配时间断言：单线程 UI 上的节流形态由「每帧至多一次扫描」的计数判据守，成本本身已由 B-8 锁。
- **不做**：真机目视以外的手感（chip 符号是否认得出、`↑↓` 图标档的可辨性、居中滚动跟手、`Ctrl+F` 被截走后 vim 用户的接受度、极窄 pane 上无跳转按钮）不在本稿验收面，须人工走查（会话锁屏下 `SendInput` 静默失效，同裁决 7.31 口径）。界面腿的用例是无头像素与文本断言，不构成「可用」的结论。

## 6 出图与复现

与 RENDER_UI / UI_SELECTION / UI_WORKSPACE_INTERACT 同一套逐格矢量法：每格一个 `<text>` 元素、色带与高亮为 `<rect>`、条内的浮层控件为 `<rect>` + 居中 `<text>`，面板高度是其行数的纯函数，判据文字排在面板框外以免压图。A1 与 A2 两张终端面板共用同一份行数据（只是有无查询之别），故其非高亮像素逐字相同这一事实本身在图上可见。PNG 由无头浏览器按 SVG 声明尺寸 1× 截图得出（生成脚本是一次性工具，不入库，与其余各稿同口径）。
