# Borealis 应用界面草图 · 总览与判据索引（draft）

> **这是什么**：应用界面的高保真草图（类 Figma 的静态稿），共四屏 + 一张总览。它回答的是**「每个界面长什么样、上面有哪些控件、每处对应哪条需求」**，评审时按每屏下方的编号判据逐条勾。
>
> **这不是什么**：不是代码形态稿，也不是终端格子的像素目标稿。三者分工如下——
>
> | 文档 | 管什么 |
> |:---|:---|
> | `codespec/UI_OVERVIEW.draft.md` + 四屏 `UI_*.draft.svg/.png`（本稿） | 界面布局、控件形态、文案、需求落点 |
> | `codespec/RENDER_UI.draft.md` + `RENDER_UI.draft.svg/.png` | 终端格子上屏后的像素判据（V1~V27）与差距清单（G-1~G-9） |
> | `codespec/UI_SELECTION.draft.md` + `UI_SELECTION.draft.svg/.png` | 选区高亮的像素判据与 `selection` 色值来源（D1~D7 已并入裁决 7.38①） |
> | `codespec/UI_WORKSPACE_INTERACT.draft.md` + 同名 `.svg/.png` | 分屏与标签条的**交互态**判据（切分 / 把手五态 / 焦点路由 / 重排 / 重命名 / 关闭确认，D1~D11 见裁决 7.47） |

## 2 全局视觉规格（四屏共用）

草图按 **1500×900 dp @100% DPI** 绘制，单位为 dp；实现时按框架缩放换算，不照抄像素。

### 2.1 颜色 token

| token | 值 | 用途 |
|:---|:---|:---|
| `win` | `#1E1F29` | 窗口底色（内容区未绘制处的兜底色，也是窗口边框基色） |
| `chrome` | `#21222C` | 标题栏、标签条底、侧栏、导航、菜单底、分隔条 |
| `raised` | `#282A36` | 活动标签、卡片、悬停态 |

### 2.3 文案口径

- 界面文案为**真实中文产品文案**（草图即文案定稿的第一版），双语经 StringTable 走 `SPEC.FEAT.PREF.05`。
- 延后能力一律带「延后 / 延后子项」角标且灰置，**不画成可用态**：ProxyJump、ForwardAgent、连接复用、snippets、十六进制视图、字体连字、kitty keyboard 等。
- 危险动作（关闭、断开）用 `red`；不可逆动作的确认按钮不放主位（屏 4 两个对话框的主按钮分别是「仍然关闭」红底与「记住该域并打开」紫底，语义不同）。

## 4 拍板结论（界面层，编号 `N`；2026-10-02 收口，全部并入裁决 7.25）

| 编号 | 问题 | 草图当前取法 | 结论 |
|:---|:---|:---|:---|
| N1 | 侧栏缺省是展开还是折叠 | 屏 1 画折叠轨、屏 2 画展开态，未定缺省 | **折叠缺省**，展开态入配置并被记住（与 `SPEC.FEAT.PREF.06` 同口径：首屏全宽给终端）。连接管理器（`SPEC.FEAT.CONN.07`）落地后不翻转缺省 |
| N2 | 标签窄态下「类型图标」与「状态角标」谁先保 | 草图按 176 dp 定宽，两者都在 | **状态角标优先**，类型图标先让位；仅在非活动标签上让位，活动标签保留图标 |
| N3 | 状态栏 10 项在 1280 dp 窗口下如何降级 | 草图只画 1500 dp，已排满 | **条目可配 + 提供 UI 入口**：每项一个开关入 `borealis::config`，入口随设置面板（裁决 7.26⑦ 的前置）。缺省全开；窗口不足以容纳已开条目时按注册次序从右向左省略，被省略项进右键菜单，不做字号压缩 |
| N4 | pane 底部角标（广播 / 连接信息 / 回看）与标签条、状态栏信息重复 | 三处都画了 | **仅分屏态显示**：单 pane 隐藏（三处信息本就重叠），分屏时保留——它是「哪个 pane 处于何种连接/回看态」的唯一线索 |
| N5 | 设置页「实时预览」是否直接用真实绘制路径 | 草图按真实路径画（与屏 1 同一套格参数） | **用真实绘制路径**：预览区复用终端视口的同一套格参数与合成链路，依赖 `SPEC.FEAT.RENDER.01`；静态假预览违背 `SPEC.FEAT.PREF.02` 的即时性口径，不予采用 |
| N6 | UI chrome 色是否随终端主题切换 | 草图 UI 侧固定一套 `#21222C` 系，终端侧随 Dracula | **不共用**：chrome 固定一套 token，切主题的视觉反馈只在终端区。主题结构**预留可选的 chrome 覆盖字段**（缺省不覆盖，入口后置），避免将来补字段时翻改已存配置 |
| N7 | 右键菜单 16 项是否需要二级分组 | 草图为单层 + 3 条分隔 | **单层 + 分隔线分区为主，低频簇收进二级子菜单**：复制语义三项开关与连接类动作各自归入子菜单，使一级可视项 ≤10；高频项不得藏进二级 |
| N8 | 命令面板的中文词条由谁提供 | 草图假定「动作名同库注册」 | **本仓 `StringTable` 维护「命令 id → 中/英词条」映射表**：`CommandRegistry` 只收英文 id（框架口径 + `AGENTS.md` §4.6 第 14 条的字面量规则），面板渲染时按当前语言查表；新增命令须同步词条，映射表集中一处以便核对（`SPEC.FEAT.PREF.05`） |
