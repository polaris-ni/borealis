## 1 范围与边界

**本期交付**：SSH 会话内的 SFTP 文件浏览面板——远程目录浏览（面包屑导航）、本地目录浏览、上传/下载（进度与取消）、新建/重命名/删除、权限与大小/修改时间显示。数据全部经 SFTP 子系统取得，**不依赖服务器额外组件**（不跑 shell 命令、不装服务端 helper）。

**不本期交付**：传输队列持久化（重启恢复）、拖拽对传（对传走按钮/双击）、chmod 权限编辑（需求只要求「权限显示」）、列头点击改排序键、传输限速、书签/收藏路径、目录对比同步（WinSCP Keep remote directory 语义）。

**会话关系（沿用既有裁决口径）**：在 CONN.02 连接复用落地之前，SFTP 面板**自开一条独立 SSH 会话**（同档案、同凭据链，`conn/ssh_dial` 共用腿），与终端会话互不干扰；面板随所属 SSH 标签关闭而关闭（见 D8）。

## 3 待裁决（D1–D9）

| # | 待决 | 选项 | 推荐与理由 |
|---|---|---|---|
| **D1** | 面板形态 | ① SSH 标签内右侧停靠面板（非模态，可开合）；② 标签内切换全屏视图（终端区被 SFTP 替换）；③ 独立标签页 | **①**。「SSH 会话内」语义最强的落点是面板随会话走（标签关闭即面板关闭），不新增标签管理负担；② 丢终端可视性、③ 把「会话内」拆成两标签。宽度待定：双栏 560 dp（各栏 260），单栏态 320 dp（与连接侧栏同宽族） |
| **D2** | 本地路径选取 | ① 面板内置本地浏览栏（`std::filesystem` 列目录，双平台可用）；② 依赖 `aurora::file_dialog`（公共 API，但真实实现仅 Win32——Linux 腿为 headless 内联回退，等于取消）；③ ① 为主、② 作 Win32 增强入口后置 | **③（本期①）**。需求原文是「双栏」浏览，内置本地栏直接命中；上传/下载不依赖系统对话框，当前 Linux 开发腿即可真机走查；`aurora/file_dialog.h` 的 POSIX 实现属框架缺口，走 Aurora 侧分流（AGENTS §5.1），不阻塞本期 |
| **D3** | 「目录树」形态 | ① 面包屑＋逐层列表导航（双击进入、向上返回）；② 真·树控件（可展开节点、懒加载子树） | **①**。SFTP 无递归列目录原语，真树=逐层 readdir 的另一种摆法，控件成本高且窄栏放不下；主流客户端（WinSCP/Termius/Tabby）均为列表导航。验收按「逐层浏览可到达任意目录」执行；评审若坚持树形态需追加树部件工作量 |
| **D4** | 「新建」范围 | ① 仅新建文件夹；② 新建文件夹＋新建空文件（0 字节，SFTP open CREAT|TRUNC 即得） | **②**。「新建」不指明对象，空文件是脚本/占位刚需且传输腿零成本；评审若收敛为①，传输腿无需改动 |
| **D5** | 权限呈现 | ① ls 字符串列（如 `-rwxr-xr-x`）＋数字八进制 tooltip；② 仅 ls 字符串；③ 字符串列＋chmod 编辑入口 | **①**。模型已备 `format_permissions`（ls 口径含 setuid/setgid/sticky）；八进制是运维习惯读法，tooltip 零版面成本。**不做 chmod**——需求只写「权限显示」，编辑权属需求外行为 |
| **D6** | 删除确认 | ① 一律二次确认（危险红按钮，目录删除文案注明「仅可删除空目录」）；② 文件直接删、仅目录确认 | **①**。SFTP unlink/rmdir 不可逆且无回收站；rmdir 不递归是传输腿既定口径，文案须明示避免「删没删干净」的困惑 |
| **D7** | 传输并发 | ① 串行队列（同时至多 1 个传输，其余排队）；② 并发 N 路 | **①**。SFTP 子系统单通道上并发多请求收益有限（协议窗口限制），串行使进度条/取消语义单一直观；队列计数 chip 呈现排队项 |
| **D8** | 会话生命周期 | ① 面板打开即连（打开时拨号，失败显示重试）；② 首次操作时懒连 | **①**。拨号+认证数秒，懒连会让首次点击卡顿且错误后置；连接中显示状态，终端标签关闭→面板关闭→`SftpClient::disconnect()`。凭据链同 CONN.09 口径（句柄/询问，不落明文） |
| **D9** | 进度回传 | ① 传输进度按固定节流（≤100 ms）合成最新值回 UI 线程；② 每块都回调 | **①**。AGENTS §25 / `SPEC.NF.PERF.06`：后台与 UI 经有界队列交换**合成后的最终值**；32 KiB 块级回调在千兆网下远超 UI 帧率，节流是纪律不是优化 |

## 5 数据流与线程模型

```
SftpPanel（UI 线程：渲染/输入/节流合成）
    │  操作请求（list_directory / mkdir / rmdir / unlink / rename / upload / download）
    ▼
有界请求队列（SPEC.NF.PERF.06）────────► SftpWorker（单工作线程，串行消费）
                                            │ 每请求调 conn::SftpClient（阻塞）
                                            │   ├ list_directory ──► sort_entries() 后整表投递
                                            │   └ upload/download ──► SftpProgress（块级）
    UI ◄── 节流合成（D9：≤100 ms 一帧）◄──┘
    │
    └ 取消 = 置 std::atomic<bool>（传输腿已实现半成品清理）
```

- 列目录结果**整表合成后投递**（排序在 worker 侧做掉，UI 只消费现成行——`sftp_model.h` 既定口径「UI 只消费算好的行」）。
- 传输进度只保留最新快照，UI 帧间至多一次重绘。
- UI 线程零阻塞 IO（AGENTS §25）：任何 SFTP 调用不进事件回调与绘制路径。

## 6 验收判据映射

- **目录树（浏览）**：D3①——面包屑＋向上/刷新＋目录置顶列表（`sort_entries`），双击进入子目录；判据按「逐层浏览可到达任意目录」。
- **上传/下载（进度与取消）**：栏间对传按钮发起，底部传输条显示进度（`SftpProgress::progress_percent`，总量未知转不确定态）与取消；取消后无半成品残留（传输腿已保证）。
- **删除/重命名/新建**：右键菜单四动作；新建范围按 D4、删除确认按 D6。
- **权限显示**：列表权限列（`format_permissions`）＋八进制 tooltip（D5①）。
- **不依赖服务器额外组件**：全部能力走 SFTP 子系统（`sftp_client` 已落），无 shell/服务端 helper。
- **性能纪律**：`SPEC.NF.PERF.06` 有界队列＋节流（D9）。
- **测试**：`utest_sftp_model`（7）与 `utest_sftp_format`（新增）全绿；面板真机走查按 AGENTS 第 33 条在实现后执行（未走查不得称「可用」）。
