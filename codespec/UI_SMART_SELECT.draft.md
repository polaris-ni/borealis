## 1 范围与边界

**本期交付**：

1. **一个纯逻辑判定** `ui::smart_span_at(row, point)`：落点严格位于同一行的一对受支持定界符之间时，返回**最内层**那一对的闭开列区间（含两端定界符）；否则回空。
2. **双击接入**：`DragMode::Word` 的按下端先求智能区间，命中即以它作为拖拽起点；未命中回退既有 `word_span_at`。
3. **受支持的配对**：`"` 与 `"`、`'` 与 `'`、反引号与反引号、`(` 与 `)`、`[` 与 `]`、`{` 与 `}`。
4. **逃逸感知**：定界符前有奇数个反斜杠时视作字面字符，不参与配对；引号按同型顺序配对，括号按单一栈做嵌套配对。
5. **单测与集成用例**：单元覆盖嵌套、逃逸、未闭合、落点在定界符上、多对并存、双宽字符；集成覆盖双击引号内、括号内、无配对回退与行级回退。

**本期不交付**（§4 在册）：

- 跨行配对：一对引号/括号跨两行时不展开，双击仍按词粒度。
- `<` 与 `>`：在 shell 里是重定向/比较运算符，误配代价高于收益，不纳入配对集。
- 智能选择规则可配（自定义正则、动作表）：本棒只有固定配对集，不新增设置键。
- 双击后的第二层「再双击扩到外层」：一次双击只取最内层一对。
- 真机走查（AGENTS §4.4 第 33 条）：手感与跟手不据此宣称「可用」。

## 2 口径（D1–D7）

### D1 触发与落点

- 只在**双击**（`click_count == 2`）的按下端求智能区间；三击仍是整行，拖拽中的当前端仍是词粒度。
- 落点必须**严格位于**一对定界符之间：`open < column < close`。落在定界符本身、配对之外或空行上都不进智能档，交回 `word_span_at`。
- 落点所在存储行已滚出可见窗时沿用既有 `mirror_line_of` 回空路径，不做额外扫描。

**理由**：双击是既有词粒度的入口，用户预期只在「词」与「更大的一段」之间升级；三击已有整行出口，不该被配对规则改写。**代价**：想选「引号本身」只能在界定符集里保留引号并逐格拖，或改界定符配置。

### D2 配对符集合

| 类别 | 字符 | 说明 |
|:---|:---|:---|
| 引号 | `"`、`'`、反引号 | 同型顺序配对；不同型互不吞并 |
| 圆括号 | `(`、`)` | 与方、花括号共用一张嵌套栈 |
| 方括号 | `[`、`]` | 同上 |
| 花括号 | `{`、`}` | 同上 |

**不纳入** `<` / `>`（shell 运算符）。配对集是**代码内固定常量**，不读 `terminal.word_delimiters`，也不新增配置键——需求只点名「引号/括号」，而一枚新键要过 schema、面板、核对表与词条六处同步。

### D3 匹配算法

1. **逃逸**：一个候选定界符若其左侧紧邻连续反斜杠的个数为奇数，视作字面字符（`"a\"b"` 的内层引号不闭合外层）。
2. **括号**：从左到右扫，开符入栈；遇到闭符时**只有栈顶同类**才配对并出栈，异类闭符忽略（不猜交叉配对）。未闭合的开符不产生区间。
3. **引号**：每种引号各自从左到右配对，遇到未逃逸的同型引号即与最近一个未配对的同型引号成对；已配对的引号不参与后续配对。
4. **选择**：收集所有配对，筛出严格包含落点的那些，取**宽度最小**的一对；宽度相同不可能发生在不同列上。引号与括号重叠时同样按「最内层」取——例如 `f("a(b)c")` 里双击 `a` 取引号那一对，双击 `b` 取圆括号那一对。
5. **返回**：`RowSpan{point.row, open, close + 1U}`，闭开区间，**含两端定界符**。

### D4 选区是否含定界符

**含**。iTerm2 的内置引号规则把引号算在命中段内；需求写「扩展选至配对符」，本稿把配对符读作边界的一部分而不是边界外的一格。于是双击 `"hello world"` 复制得到带引号的整段。

**代价**：想只复制引号内的内容时，用户需要从配对内向外逐格拖，或依赖应用的 `terminal.word_delimiters` 逐词选。**备选档**（不含定界符）被否：它与「选至配对符」的字面读法相反，且会让双击在视觉上少一格，难以解释。

### D5 回退

- 没有严格包含落点的配对（包括未闭合、类型不匹配、落点在定界符上）⇒ 完整交回既有 `word_span_at`。
- 回退结果仍按原判据处理：落在空格/制表/界定符上回空，双击即无选区（7.39④）。
- 智能档不改变 `word_span_at` 的任何一行实现，既有单测与集成用例继续守着原口径。

### D6 拖拽

- Press 时若命中智能区间，记下 `pressed_smart_span_`；`extend_selection` 的按下端优先取它。
- Move/Release 的当前端落在配对区间内（含两端定界符）时保持整段，移出后按词粒度；跨行拖动于是得到「从配对起点到当前词尾」的流式选区。双击的抬起就在按下那一格上，若照常按词粒度重算会把整段缩回一个词（实装时由集成用例逮住并修正）。
- 每次新的 Press 先清掉上一枚 `pressed_smart_span_`；未命中时不留空壳。
- 不把智能档做成第四个 `DragMode`：它只改变**起点**，不改变拖拽中的粒度判定，做成枚举会诱使后续在 Move 端也找配对，产生「拖动时不断换框」的不可解释手感。

### D7 复制与视觉

- 复制、像素高亮、失焦降级、scrollback 漂移补偿、copy-on-select、右键菜单「复制」全部复用既有路径，零改动。
- 不新增视觉层：智能选区就是普通 `Selection`，绘制侧只看 `bands_`。
- 不新增命令与快捷键：双击本身已是入口。

## 3 判据

**单元（`utest_selection`）**：

1. 双引号内含空格的一段，落点在中部 ⇒ 区间从开引号到闭引号（闭开右界 = 闭引号 + 1）。
2. 圆括号、方括号、花括号、单引号、反引号各一例。
3. 嵌套 `f("a(b)c")`：双击 `b` 取圆括号，双击 `a` 取双引号。
4. 未闭合、异类闭符、落点在定界符上 ⇒ 回空。
5. 逃逸引号与逃逸括号不参与配对。
6. 双宽字符夹在配对内 ⇒ 区间仍按列给出，整字符进复制文本。
7. `<`/`>` 不成对。

**集成（`itest_render_viewport`）**：

1. 投喂 `say "hello world" now`，双击 `hello`：像素上引号与整段都换成 selection 底，`selected_text()` 为 `"hello world"`（含引号）。
2. 投喂 `run (alpha beta) end`，双击 `alpha`：整段含括号入选。
3. 无配对的行双击仍只选词；落在引号上双击仍无选区。
4. 双击配对后拖动到相邻词，选区从配对起点延伸到当前词尾（起点不被词粒度覆盖）。

**变异自证（四支）**：

- 去掉「严格在内」判据改 `open <= column <= close` ⇒ 落点在定界符上的用例红。
- 去掉逃逸判据 ⇒ 逃逸引号用例红。
- 嵌套时改取最外层 ⇒ 嵌套用例红。
- 拒绝 `<`/`>` 的判据去掉 ⇒ `<` 用例红。

## 4 在册边界

- 跨行配对未做；一行内的配对是本棒全部射程。
- 引号不支持反斜杠以外的转义惯例（SQL 的双写引号 `''` 会被当作一对空引号 + 后续重新配对，属已知形态）。
- 智能选择规则不可配；`terminal.word_delimiters` 与配对集互不影响。
- 真机双击手感、选中一整段后的视觉边界、与链接悬停层同框时的观感未走查；Windows/MSVC 未编译验证 ⇒ 不称「可用」。
