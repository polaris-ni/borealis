## 2 逐面板判据

**面板 1：切分、并入与塌缩（`SPEC.FEAT.WS.02` 四义）**

- ① 未分屏＝单叶工作区，**无把手、无描边**（判据 11）。
- ② `Ctrl+Shift+D` 向右切一刀：新 pane 落 target 右侧、**当场选中**并挂新会话；左格尺寸逐字不动（判据 1）。
- ③ 三栏＝**一层三子**而非两层二元嵌套（判据 4）；同轴再切并进父层作兄弟（裁决 7.42①）。
- ④ 换轴才嵌套——左列竖排、右列横排 ⇒ 右侧自成一个容器层；深度不设上限（判据 4）。
- ⑤ 关闭 pane 后兄弟就地合并、只剩一子的层当场塌缩；被关的是焦点格时焦点交给**移除前**阅读序的下一位（判据 3；裁决 7.42⑥）。进程已退出的 pane 关闭后回看内容仍在，属会话侧事实、不由界面腿决定。

**面板 2：分隔条（把手）的五个状态**

- ⑤ 静止＝chrome 底 + `line2` 把手；把手窄于命中区，缝隙不吃 pane 内容（判据 5）。
- ⑥ hover＝把手染 `accent`、光标改双向箭头，**命中区不变**（否则一进一出会抖动，判据 6）。
- ⑦ 拖拽中＝Press 命中即进入拖拽；框架在 Press 时捕获整条命中链，故拖出窗口仍收 Move；沿轴位移即时折成该层相对长度并标脏，**松手才去抖下发尺寸**（判据 7 与 24）。
- ⑧ 顶到最小值＝钳在 `max(20 列, 3 行)` 的边界上，是**顶住而非越界**，松手不反弹——`layout` 与 `move_divider` 都是 const，钳位不写回相对长度（判据 8；裁决 7.42⑦）。
- ⑨ 双击该把手 ⇒ 本层等分；键盘档 `Ctrl+Shift+0`（判据 9）。

**面板 3：焦点标识与方向键路由**

- ⑪ 焦点 pane 四周 2 dp `accent` 内描边，压在格子上、不改行列数（判据 11）。
- ⑫ `Alt+→` 从 A 到 B、`Alt+↓` 从 A 到 C，**跨层也按几何路由**：先比垂直间隙（投影重叠者算 0），再比主方向间隙，同分取布局序首个（判据 12 与 13；裁决 7.42⑪）。
- ⑬ 右图是负例：跨过当前 pane 的那一格**不在「这个方向」上**，排除而非钳到最近；无候选则焦点原地不动，不绕到对角（判据 13）。
- 裸方向键恒归会话——`vim` / `tmux` 不可让渡，故需求原文的「方向键路由」解释为带 Alt 修饰（§3 D1）。路由只改**模型焦点**，随后同步框架焦点到该 pane 的视图，键盘输入因此不需要第二次转发。

**面板 4：键位总表**——本棒全部键位在图上一处列齐，判据 9 / 10 / 12 / 17 / 20 / 21 各引用其中一行；派发通道见 §3 D2。

**面板 5：标签条的五态（×2 放大绘制）**

- ⑭ 活动＝`raised` 底 + 2 dp `accent` 下划线；普通＝chrome 底；hover＝`sel` 底 + 关闭钮显形；窄态＝名字取省略号且**非活动格先让掉类型图标**（裁决 7.25 N2 的让位序，判据 14）。
- ⑮ 关闭钮只在 hover 与活动格显形，命中区＝栏位右端 20 dp；栏位其余区域是选中 + 拖拽落区（判据 15）。
- ⑯ 拖拽重排＝Press 即选中，越过 4 dp 的拖拽阈值才进入拖拽：原格留半透明占位、被拖格跟手、两格之间画 2 dp `accent` **落点导引线**；松手按落点中心折成 `TabStrip::move` 的目标下标，其基准是「其余标签」（裁决 7.43②）。落点仍在原格＝只选中，不重排。
- 「＋」固定右端、不参与溢出滚动（判据 21）。

**面板 6：就地重命名**

- ⑰ 入口＝双击名区或 `Ctrl+Shift+R`；编辑器是框架 `TextInput` 的**子类**（该件无取消与失焦回调，覆写 `on_key_event` 补 Esc、覆写 `on_focus_change` 补失焦提交，属公共 API 可组合，不登记缺口）。
- 三个收口：`Enter` 提交 / `Esc` 取消（原值还原）/ 点别处＝失焦提交；**空串提交＝撤销重命名**，让位给下一级来源（裁决 7.43③），故不另立「恢复默认名」这个动作。
- 编辑期间工作区键位不响应——焦点不在 pane 上，这是 D2 取「随焦点」的直接结果，不需要额外的模态标志。

**面板 7：关闭前确认与末位标签**

- ⑱ 判据＝该标签**任一** pane 的会话进程仍在（`Session::alive()`）；全部已退出则直接关、不再问（判据 18）。
- ⑲ 一次确认关掉整张标签（含其全部 pane），不做逐 pane 追问——多 pane 逐格问会把确认变成打地鼠（判据 19）。对话框沿用 `au::Dialog` + `aurora::confirm`，主按钮「仍然关闭」红底（裁决 7.25 的文案与配色口径）。
- ⑳ 只剩这一格标签时 `TabStrip::close` 回 `false`（末位不归本件关，裁决 7.43④）⇒ 装配层转而关窗口 `Window::close()`；「关到空就退出」的判定**只在这一处**。

**面板 8：栏位宽与溢出滚动**

- ㉑ 总宽超过可用宽时走**横向偏移**而不是压缩栏位（压缩会让「实测栏位宽」变成第二个真值源）；切换 / 新建标签后把选中格自动滚入可见区；滚轮的纵向增量折成横向偏移（框架无水平滚动件，属裁决 7.13② 的应用侧组合）。

## 3 决策点（已拍板：全取建议项，逐条理由与代价见裁决 7.47①）

| # | 议题 | 选项 | 影响面 |
|:---|:---|:---|:---|
| **D1** | 方向键路由的触发键 | ① **`Alt+方向键`**〔建议〕；② 裸方向键；③ `Ctrl+方向键` | ② 会把 `vim` 的导航键吃掉，与 `SPEC.FEAT.INTERACT.01` 直接冲突；③ 与终端内 `Ctrl+←/→`（部分 shell 的词跳转）冲突；① 的代价是多按一个修饰 |
| **D2** | 本棒键位的派发通道 | ① **焦点 pane 的按键入口前置过滤**〔建议〕；② 框架 `ShortcutRegistry`；③ `Window::set_key_pre_handler` | ② 两条实测理由不可用：它**先于任何控件**派发（会抢走就地重命名与模态对话框期间的键），且 `KeyCombo::matches` 是修饰位**精确相等**，而 Win32 在窗口获得激活时把 NumLock 播种进事件修饰位且不清除 ⇒ NumLock 开着时锁定态组合恒不匹配（登记 **G25**，**该腿已于 2026-10-04 回货闭合，而前一条仍成立**，见裁决 7.51③）；③ 是**替换**语义而非链式，装上就顶掉框架自己的快捷键通道 |
| **D3** | 最小 pane 的口径 | ① **`max(20 列 × 格宽, 3 行 × 格高)` 现算**〔建议〕；② 固定 dp | ② 在 6 pt 与 72 pt 字号下差一个数量级，「最小」就成了「能装下多少像素」而非「还能不能用」；① 的代价是 `LayoutSpec` 要随格步长重算（每帧一次，纯算术） |
| **D4** | 等分与步进的触发形态 | ① **等分＝把手双击 + `Ctrl+Shift+0`；步进＝`Ctrl+Alt+方向键`**〔建议〕；② 仅键盘；③ 仅鼠标 | ②③ 各缺一半，而 `SPEC.FEAT.WS.02` ③ 的「键盘调整」与「拖拽」是同一件事的两个入口，须共用 `move_divider` / `equalize` 一条路径 |
| **D5** | 切分新 pane 挂什么 | ① **新会话**（M1 只有本地终端）〔建议〕；② 复制焦点 pane 的会话输出 | ② 属 `SPEC.FEAT.WS.09` 的广播语义，现在做等于提前实现它，且本仓还没有「同源会话」的生命周期模型 |
| **D6** | 栏位宽与溢出 | ① **实测 + 钳 `[96,240]`，溢出走横向滚动**〔建议〕；② 等宽压缩；③ 缩成下拉 | ② 会让「窄态」与「溢出」两件事互相掩盖，且压到 96 dp 以下时名字全成省略号、失去识别；③ 与判据 15 的关闭钮命中区冲突 |
| **D7** | 就地重命名的编辑器 | ① **框架 `TextInput` 的子类**〔建议〕；② 视口内自绘一个编辑态；③ 模态对话框 | ② 要在 pane 之外重做一套光标、选区与 IME 组合，而 `TextInput` 已有这些（`SPEC.FEAT.INTERACT.06` 的候选窗定位也已在框架侧）；③ 打断感与「改个名」不成比例 |
| **D8** | 关闭前确认的判据与粒度 | ① **任一 pane `alive()` + 一次确认关整张标签**〔建议〕；② 逐 pane 追问；③ 只看选中 pane | ② 多 pane 时是 N 次对话框；③ 会静默杀掉未选中 pane 里跑着的任务 |
| **D9** | 焦点标识形态 | ① **2 dp `accent` 内描边、仅分屏态**〔建议〕；② 外描边；③ 给 pane 加标题条 | ② 会挤掉一圈内容或在窄 pane 上把相邻格盖住；③ 是 chrome 且与「终端里没有额外的条」冲突。单 pane 不画——描边等于窗口边，无信息 |
| **D10** | 尺寸去抖的归属层 | ① **工作区层**（一处 `set_timeout` 取消-重排）〔建议〕；② 视口层各自去抖 | ② 时同一帧里 N 个 pane 各起一个定时器，连续 resize 的下发次数是 N 倍；① 的代价是 `TerminalView` 要把「期望行列」交给注入的 sink 而非自己直发（缺省 sink 仍直发，故既有像素与集成用例零改动） |
| **D11** | 帧泵范围 | ① **全部 pane 的视图每帧都排**（含隐藏标签）〔建议〕；② 只排选中标签 | ② 时隐藏标签的脏队列积压到背压上限、切回来先看到旧帧；① 的代价是每帧多走 N 次「取队列 + 读网格」，而隐藏标签通常 ≤5 个 |

## 4 与现状的差距 → 界面腿须达到的条目

> 本节的六条差距是**出稿时**（2026-10-03，裁决 7.47）的盘点，逐条标注当前处置：「**已达**」＝该条所要求的件已落地并有集成用例证人（回写见裁决 7.49 与 `codespec/CHANGELOG.md` v0.46）；「**未达**」＝仍在排队，本条继续作为待办留痕。

1. **pane 容器 widget 不存在**〔**已达**（2026-10-04，`src/ui/workspace_view.{h,cpp}`）〕：框架无绝对定位件（`Stack` / `Grid` / `Splitter` 各只覆盖一种布局，架构 §8.1），故自研一个把 `ui::PaneTree::layout` 的矩形表按 dp 落到子节点上的容器——按裁决 7.13② 属「公共 API 可组合出来的交互体验」，留在本仓、不登记缺口。
2. **把手命中与拖拽未接**〔**已达**（2026-10-04，同件；判据见 `itest_workspace_layout`）〕：`PaneDivider` 的命中区要出现在 `on_hit_test` / `on_hit_test_chain` 里（框架 `Splitter` 的写法是「把手区命中自身，且链上必须返回该节点」，否则派发器把该 Press 当点击空白丢弃）；拖拽位移经 `move_divider`，松手才去抖下发。
3. **逐 pane 行列下发未接**〔**已达**（2026-10-04，去抖落 `ui::GridSizeDebounce` + 工作区层一处 `set_timeout`）〕：`ui::make_geometry` 已能按矩形出行列、`TerminalView::request_grid_size` 已能「真变了才发」，缺的是 `SPEC.FEAT.XFER.01` 的去抖合并，与「会话启动 / 切分挂载 / 切标签各下发一次初始尺寸」三条时机（判据 24）——**「切标签下发」那一腿随标签条（下条）才成立**，本件只覆盖前两条时机。
4. **标签条不存在**〔**未达**〕：栏位宽实测、五态、拖拽重排、就地重命名、关闭确认、溢出滚动六件全在界面腿；`ui::TabStrip` 只是真值源。
5. **装配层是单会话**〔**未达**〕：`src/main.cpp` 现在只造一个 `Session` + 一个 `TerminalView`，须改成「标签 → pane 树 → 每 pane 一个会话与视图」，并把帧唤醒、OSC 标题落地、剪贴板落地件三条按会话各接一份（判据 25）。**因此 `ui::WorkspaceView` 至今用户不可见**——本棒的落地面是「件本体 + 集成用例」，不是「可操作的分屏」。
6. **框架侧一条新缺口**〔**已达**（本棒按 D2① 的通道交付，不经 `ShortcutRegistry`）〕：`KeyCombo::matches` 的修饰位精确相等对**锁定态位**不可用（D2 的实测理由，登记 **G25** 并派发 Aurora 侧）；本棒**不等不绕**——按 §3 D2① 的通道交付，G25 回货后键位仍可原样迁回 `ShortcutRegistry`，因为绑定表是纯逻辑件（只比 Shift / Ctrl / Alt / Meta 四位）。**回货后的复核结论（2026-10-04，裁决 7.51③）**：G25 已闭合、绑定表口径与框架 `matches` 至此逐位一致，但「可原样迁回」那句**不成立**——D2 里 ② 的第一条理由（快捷键先于任何控件消费、`ShortcutScope::Focus` 只判「有没有焦点控件」）实测仍在，故本棒键位照旧走前置过滤，未来的迁移另有跨仓前置而不动任何判据。

## 5 验收判据（拍板并实现后）

- **纯逻辑**：`ui::PaneTree` / `ui::route_focus` / `ui::TabStrip` 的判据已由 `utest_pane_tree`（18 例）与 `utest_tab_strip`（25 例）覆盖（裁决 7.42 / 7.43），本棒**不重复断言**它们；新增的纯逻辑件只有键位绑定表（吃 `term::KeyPress`，只比 Shift / Ctrl / Alt / Meta 四位）与「期望行列 → 去抖后一次下发」的合并判据，各补 `utest_*`。
- **像素 / 集成**（`tests/integration/itest_render_viewport.cpp` 与新的 `itest_workspace_layout.cpp`，`HeadlessSurface`）：切分后两 pane 的**行列数各等于自己的矩形 ÷ 格步长**（不是共享一份）、把手拖拽后比例改变而**总列数守恒**、`Alt+方向键` 后焦点视图变了而选区与滚动位置不动、标签重排后 `TabStrip::tabs()` 次序与栏位左缘次序一致、连续 resize 期间 `Session::resize` **只被调用一次**（去抖的证人）、隐藏标签排两帧后切回来内容与权威网格一致（判据 25）。
- **不做**：真机走查以外的手感（拖把手跟手、`Alt+→` 连按、重排导引线的落点直觉、就地重命名的 IME 组合态）不在本稿验收面，须人工走查（会话锁屏下 `SendInput` 静默失效，同裁决 7.31 口径）。集成用例是无头像素与文本断言，不构成「可用」的结论。
