## 1 形态总览

**一次批次 ＝ worker 内的一条请求串行跑完三步**，UI 只见三样东西：总进度、失败问人框、结束留痕。

```
发起（右键「下载」/「上传到此」命中目录条目）
   │  Request{kind: BatchDownload | BatchUpload, a: 目录路径, local: 目标目录}
   ▼
worker：① 预枚举（远端递归 list_directory / 本地 recursive_directory_iterator）
        → conn::plan_batch_transfer(entries树) 折叠成 {files:[{源相对路径,字节}], dirs:[…], total_bytes}
        越守卫线（D4）→ 整批拒绝，落留痕，不弹框
      ② 镜像建目录（下载＝本地 create_directories；上传＝远端逐级 make_directory）
      ③ 逐文件投递（download_file / upload_file，进度折进批次总账）
        单件失败（非 Cancelled）→ §2 的决策往返等人答：跳过＝记数继续；中止＝退出循环
   ▼
结束：TransferDone{ok, 成/败/跳计数} → 传输条落「N 成 / M 跳 / K 败」留痕一行 + 复列目标栏
```

- **取消**：批次没有独立取消钮——传输条那枚既有「取消」打 `cancel_flag_`，语义改判为**取消整批**（当前件清半成品，队列即止）。
- **队列计数**：批次对 `transfers_posted_` 恒贡献 1（F3），批次内文件数不挤进 chip；文件级计数只出现在结束留痕与问人框文案里。
- **总进度**：扩展 latest-value 快照一份（批次态下 `bytes_done` 为批次累计、`total_bytes` 为预枚举总量），单文件传输的快照形态一字不动。

## 2 决策往返（本棒唯一的新跨线程件）

```
worker：TransferAsk{path, error, seq} 投收件箱 → 在 cv 上等「答话槽」（四出口：人答 / 60 s 超时 / 取消旗标 / 面板析构）
UI   ：tick 取到 Ask → au::confirm「跳过 / 中止」→ 答话写「决策槽」并 notify
四出口：答话按人所选取；60 s 无人答＝按缺省焦点档「中止」（关框/浮层被摘同落此档——实现把初稿的被动档改判为主动超时，worker 不无限等）；cancel_flag_ 置位＝中止；析构＝中止。
```

- 问人框期间 worker **不持任何传输句柄**（当前件已按返回值收尾，半成品清理已完成或已放弃），等待不阻塞 UI（AGENTS §4.5 第 25 条：等待在 worker 侧，UI 只弹框）。
- 面板析构路径 `Shutdown` 请求与既有 join 序负责把「永远没人答」这一档收口成中止；该等待件本身做成纯逻辑 `BatchDecisionLatch`（cv + 槽 + 四出口），**有 utest 证人**——面板整件没有可注入的假服务器（F6），latch 单独测不会因此落空。

## 3 裁决（D1–D8，2026-10-25 收口：均按推荐，人逐条裁「全部按推荐」）

| # | 待决 | 选项 | 推荐 | 理由与代价 |
|---|---|---|---|---|
| **D1** | 符号链接/特殊文件在批次里的处置 | ① 一律跳过并计数；② 软链按目标文件复制；③ 软链跟随（环风险） | **①** | 条目卡不跟随软链是既有模型口径（`SftpEntryKind::Symlink`「不跟随」）；② 需要 stat 目标、多一次往返且 Windows 语义存疑；③ 有环死风险。代价：含软链的树「N 跳」计数会出现，留痕文案必须解释得清 |
| **D2** | 本地已有同名文件（下载方向） | ① 覆盖（传输腿现语义，成功即真）；② 预枚举后一次性问「覆盖/跳过已存在」；③ 逐件问 | **①** | 单文件下载今天就是覆盖（既有腿零改动），批次逐件问（③）会把 §2 那条往返变成每文件一次、大目录树下变成拷问；② 要 UI 线程做本地 stat（违 §25）或加第二条 worker 往返，成本超需求。代价：覆盖不可逆，确认框文案须写明「已存在的同名文件将被覆盖」 |
| **D3** | 远端已有同名（上传方向） | ① 覆盖；② 改名（`name (1)`）；③ 拒绝 | **①** | 与 D2 同向；改名要逐件探测远端存在性（N 次额外往返），拒绝则让「重传一批」变成手工清场。`upload_file` 现语义即 trunc 覆盖 |
| **D4** | 预枚举守卫线 | ① 深度 64 ＋ 文件数 100 000，越线整批 fail-closed 拒绝（留痕说明，不弹框）；② 不设限；③ 只设字节上限 | **①** | 坏目录树（/proc、自指挂载）会淹死 worker 与本地栏；② 的失控成本是整条 SFTP 会话卡死；③ 拦不住深环。100 000 是拍脑袋上限，按「预枚举期间该 worker 什么都干不了」的口径取保守值。代价：超限的真实大树传不了，文案要说「请压缩成单文件再传」 |
| **D5** | 发起前的确认与词条 | ① 弹框确认一次（文案带目录名与「将覆盖同名文件」），词条 +N；② 不确认直接排队 | **①** | 破坏性面（D2/D3 的覆盖）须先于动作可见；② 省一个框但把手感成「双击即走」的危险动作。代价：ARB 两档各加词条（v2 管线，构建期 `gen_i18n`，裁决 7.150 口径） |
| **D6** | 批次排队期间面板其余操作 | ① 照常投递进队列，排在批次后执行；② 批次在途即置灰非传输操作 | **①** | 串行队列（F4）本就有排队语义，置灰是新的 UI 状态机而收益只是「看着干净」；用户在批次后排队一个列目录无害。代价：批次跑完前所有操作都在等，留痕文案要交代「队列里有 K 节」 |
| **D7** | 失败问人框的焦点缺省 | ① 缺省焦点＝**中止**；② 缺省＝跳过 | **①** | 「没想清楚就回车」应落在可恢复档（中止只损失后续件，跳过可能漏掉关键文件而用户以为传全了）；与 D13 先例的保守向一致。代价：连续多件失败时回车连中止，手感偏硬 |
| **D8** | 证人分层 | ① 纯逻辑件（`plan_batch_transfer` 折叠 + `BatchDecisionLatch` 三出口）配 utest；面板/worker 真传输腿登记「无 sshd 无证人」在册；② 本棒顺带给 `SftpClient` 开注入点补 itest | **①** | ② 是给整条传输腿动手术（违「一个改动一个意图」），且 F6 那条物理事实是既有裁决如实登记过的；递归计划与决策闸恰是本棒新增的两枚纯件，各自可测。代价：批次循环的接线腿（`run_batch`）与 `main.cpp` 同类——源码审查 + 真机走查担保（裁决 7.83 句式） |

## 5 验收判据映射

- 需求「上传/下载（进度与取消）」在批次上的读法：总进度可判（预枚举总量）、取消即整批止且当前件无半成品。
- 首败问人：`BatchDecisionLatch` 四出口各有 utest；「跳过继续 / 中止收摊」两条分支的批次循环本体按 D8① 登记为无自动化证人（接线腿），归真机走查。
- 守卫线：`plan_batch_transfer` 的拒绝档有 utest（构造越线树形）；真树上的越线归走查。
- 覆盖语义（D2/D3①）：确认框文案上屏即判据，真覆盖后果**不进自动化**（须真 sshd），归走查。
- 结项读数须报：非 e2e CTest 项数与 runner 案数、变异自证台账（latch 四出口与折叠件各注变异指名红案，AGENTS §4.4 第 22 条；实落三刃见裁决 7.151⑥与 CHANGELOG v0.151）。
